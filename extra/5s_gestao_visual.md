## Capítulo 18-A: 5S e Gestão Visual de Chão de Fábrica

### A pergunta de engenharia

*A área foi organizada mês passado. Hoje tem caixa no chão outra vez, ferramenta duplicada na
bancada, etiqueta vermelha que ninguém removeu. O que quebrou?*

Nada quebrou — o 5S nunca chegou ao quinto S. Sort, Set in Order e Shine são um evento: dá para
fazer numa tarde e mostrar fotos de antes/depois. Standardize e Sustain são uma disciplina: exigem
que alguém volte todo dia. A maioria dos programas de 5S que "não funcionam" não falhou na
organização — falhou em transformar organização em hábito.

## 2 · Onde a disciplina cai primeiro

Auditoria típica de 5S, por pilar:

```plotly
5s-radar
```

O padrão se repete em quase toda auditoria real: os três primeiros pilares pontuam bem — são
visíveis, fotografáveis, fáceis de vender numa apresentação. **Sustain** é sistematicamente o mais
baixo, porque é o único que não produz um resultado visual imediato — produz a *ausência* de
regressão, o que ninguém fotografa.

### Por que o 5S falha (as três causas mais comuns)

| Causa | O que acontece | O sintoma |
|---|---|---|
| **Parar no Shine** | Sort, Set e Shine são feitos; Standardize e Sustain, não. | O caos volta em duas a quatro semanas. |
| **Confundir com estética** | 5S tratado como "deixar bonito", não como eliminar desperdício e melhorar fluxo. | Área bonita, mas sem ganho de produtividade — e a gerência perde interesse. |
| **Sem padrão visual** | Não há shadowboard, etiqueta ou código de cor. | Cada pessoa organiza do seu jeito; a "ordem" não sobrevive à troca de turno. |

> **A verdade do 5S.** Um "dia de limpeza" anual não é um sistema — é um evento que a bagunça
> absorve e devolve em duas semanas. 5S não é uma faxina. É uma disciplina diária embutida em como
> o trabalho é feito.

O padrão de Pareto aqui é quase sempre o mesmo: "item fora do lugar" e "sujeira acumulada" somados

## 4 · Código de cores de piso — o supervisor silencioso

Marcação de piso é gestão visual em sua forma mais barata: qualquer pessoa, mesmo sem treino,
reconhece o significado em segundos.

| Cor / padrão | Significado típico |
|---|---|
| **Amarelo** | Corredores, faixas de tráfego, zonas de trabalho gerais |
| **Azul** | Estágio de matéria-prima / material recebido |
| **Verde** | Produto acabado / área segura |
| **Laranja** | Produto retido para inspeção |
| **Vermelho** | Defeito, refugo, área de contenção |
| **Preto** | Trabalho em progresso (WIP) |
| **Branco** | Armazenamento de ferramentas e equipamentos |
| **Preto + amarelo (hachurado)** | Zona de perigo — manter livre |
| **Vermelho + branco (hachurado)** | Manter livre para acesso de segurança/emergência |

## 5 · Gestão visual além do piso: as ferramentas que sustentam o Sustain

| Ferramenta | O que resolve | Frequência típica |
|---|---|---|
| **Job Element Sheet (JES)** | Passo a passo do posto, com foto e "o porquê" de cada ponto-chave — não só o "o quê". | Consultado a cada troca de operador |
| **Quadro hora a hora** | Planejado vs. real por hora, causa de desvio e ação tomada — expõe a perda no mesmo turno em que ela acontece. | A cada hora |
| **Quadro Kamishibai** | Cartão verde/vermelho por item de auditoria, por dia da semana. Um cartão faltando já é sinal de auditoria pulada. | Diária, por amostragem |
| **Sala Obeya** | Sala física com visão, estratégia, SQDC do dia, backlog de problemas e ações — tudo num único lugar. | Ritmo semanal/mensal |
| **One Point Lesson (OPL)** | Uma lição, uma folha, com foto do "errado" e do "certo" lado a lado. | Publicada a cada desvio relevante |

## 6 · Pontuando uma auditoria de 5S

```py-r
--- python
import numpy as np

# Auditoria de 5S: 5 pilares, 4 perguntas cada, escala 0-5
pilares = ["Sort", "Set in Order", "Shine", "Standardize", "Sustain"]
notas = np.array([
    [4, 4, 5, 3],   # Sort
    [5, 4, 4, 4],   # Set in Order
    [4, 3, 4, 4],   # Shine
    [4, 4, 3, 5],   # Standardize
    [2, 3, 3, 2],   # Sustain
])

media_pilar = notas.mean(axis=1) / 5 * 100     # em % do maximo
score_geral = notas.mean() / 5 * 100

for p, m in zip(pilares, media_pilar):
    status = "OK" if m >= 80 else ("ATENCAO" if m >= 60 else "CRITICO")
    print(f"{p:<14s} {m:5.1f}%   [{status}]")
print(f"\nScore geral 5S: {score_geral:.1f}%")

pior = pilares[np.argmin(media_pilar)]
print(f"Pilar mais fraco: {pior} — e o candidato natural a plano de acao no proximo ciclo.")
--- r
pilares <- c("Sort", "Set in Order", "Shine", "Standardize", "Sustain")
notas <- matrix(c(
  4,4,5,3,
  5,4,4,4,
  4,3,4,4,
  4,4,3,5,
  2,3,3,2
), nrow = 5, byrow = TRUE)

media_pilar <- rowMeans(notas) / 5 * 100
score_geral <- mean(notas) / 5 * 100

for (i in seq_along(pilares)) {
  status <- if (media_pilar[i] >= 80) "OK" else if (media_pilar[i] >= 60) "ATENCAO" else "CRITICO"
  cat(sprintf("%-14s %5.1f%%   [%s]\n", pilares[i], media_pilar[i], status))
}
cat(sprintf("\nScore geral 5S: %.1f%%\n", score_geral))
cat(sprintf("Pilar mais fraco: %s\n", pilares[which.min(media_pilar)]))
```

### Erros comuns

1. **Fazer Sort/Set/Shine e chamar de "5S implementado".** Sem Standardize e Sustain, é limpeza —
   não sistema.
2. **Auditar sem consequência.** Uma auditoria que não gera plano de ação com dono e prazo é
   burocracia, não gestão visual.
3. **Marcação de piso inconsistente entre áreas.** Se o código de cor muda de setor para setor, ele
   deixa de ser universal — e de funcionar.
4. **Tratar o 5S como projeto de uma vez, não como rotina.** "Fizemos 5S em março" é a frase que
   precede "por que está bagunçado outra vez em maio".
5. **Ignorar o Sustain nos indicadores de gestão.** Se o dashboard de qualidade só mostra Sort/Set/
   Shine, ninguém vai notar quando Sustain está caindo — até a área voltar ao caos.
