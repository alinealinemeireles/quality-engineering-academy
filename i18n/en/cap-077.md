## Chapter 77: Response Surface Methodology: CCD, Box-Behnken, and Optimization
### The engineering question

*I already know which factors matter. Where's the optimum, and how flat is it there?*

Screening answers "who matters." Response surface answers "where to operate." These are different phases with different designs, and using one in place of the other wastes runs or produces wrong answers.

| Phase | Goal | Design | Model |
|---|---|---|---|
| **Screening** | Filter many factors | $2^{k-p}$ resolution III/IV | Main effects |
| **Characterization** | Interactions and curvature | $2^k$ + center points | Linear + interactions |
| **Optimization** | Locate the optimum | CCD or Box-Behnken | **Full quadratic** |

### The quadratic model

$$y = \beta_0 + \sum_{i} \beta_i x_i + \sum_{i} \beta_{ii} x_i^2 + \sum_{i<j} \beta_{ij} x_i x_j + \varepsilon$$

It needs at least 3 levels per factor — which is why 2-level designs don't work.

### The two main designs

**CCD — Central Composite Design**

Made up of three parts: a factorial (or a fractional of resolution ≥ V), **axial points** at distance $\alpha$ from the center, and replicated center points.

$$\alpha = (2^k)^{1/4} \quad \text{for rotatability}$$

*Rotatability* means the prediction variance depends only on the distance from the center, not the direction — a desirable property when you don't know in advance which direction the optimum lies in.

An important variant: the **face-centered CCD** ($\alpha = 1$) keeps everything inside the cube. It loses rotatability but is indispensable when the extreme levels are physically impossible (a concentration can't exceed 100%, a valve can't open past its maximum).

**Box-Behnken**

Combines pairs of factors at the extremes with the rest at the center. **It never uses the vertices** — no run has every factor at the extreme simultaneously. This is decisive when the combination of all the extremes is dangerous, impossible, or destructive (maximum pressure *and* maximum temperature).

| | CCD | Box-Behnken |
|---|---|---|
| Levels per factor | 5 (or 3 with faces) | 3 |
| Uses vertices | Yes | **No** |
| Runs (k=3) | 20 | 15 |
| Runs (k=4) | 30 | 27 |
| Built in stages | **Yes** (add to the existing factorial) | No |
| Extrapolation at the corners | Good | Poor |

> **Sequential construction is CCD's biggest advantage**: if you already ran a $2^k$ with center points and detected curvature, you just add the axial points. The earlier runs aren't lost.

### Worked example: optimizing a process with 3 factors

```py-r
--- python
import numpy as np
import pandas as pd
from itertools import product
import statsmodels.formula.api as smf
from scipy import stats, optimize
import matplotlib.pyplot as plt

rng = np.random.default_rng(9090)
k = 3
alpha = (2**k)**0.25       # rotatibilidade

def ccd(k, n_centro=6, alpha=None, faces=False):
    if alpha is None: alpha = 1.0 if faces else (2**k)**0.25
    pts = [list(c) for c in product([-1,1], repeat=k)]           # fatorial
    for i in range(k):                                            # axiais
        for s in (-alpha, alpha):
            p = [0.0]*k; p[i] = s; pts.append(p)
    pts += [[0.0]*k]*n_centro                                     # centrais
    return pd.DataFrame(pts, columns=[f"x{i+1}" for i in range(k)])

def box_behnken(k, n_centro=3):
    pts = []
    for i, j in [(a,b) for a in range(k) for b in range(a+1,k)]:
        for si, sj in product([-1,1], repeat=2):
            p = [0.0]*k; p[i] = si; p[j] = sj; pts.append(p)
    pts += [[0.0]*k]*n_centro
    return pd.DataFrame(pts, columns=[f"x{i+1}" for i in range(k)])

d = ccd(k, n_centro=6, alpha=alpha)
bb = box_behnken(k)
print(f"CCD rotatável (k={k}): {len(d)} corridas, alpha = {alpha:.3f}")
print(f"   {2**k} fatoriais + {2*k} axiais + 6 centrais")
print(f"Box-Behnken (k={k}): {len(bb)} corridas, sem vértices")
print(f"   Corrida com todos os fatores no extremo: "
      f"CCD tem {int((d.abs()==1).all(axis=1).sum())}, Box-Behnken tem "
      f"{int((bb.abs()==1).all(axis=1).sum())}\n")

# --- Verdade: superfície com máximo interior ---
def verdade(x1, x2, x3):
    return (86.0 + 3.4*x1 + 1.9*x2 - 0.8*x3
            - 2.9*x1**2 - 2.2*x2**2 - 1.1*x3**2
            + 1.7*x1*x2 - 0.6*x1*x3)

d["y"] = verdade(d.x1, d.x2, d.x3) + rng.normal(0, 0.5, len(d))

# --- Ajustar o modelo quadrático completo ---
form = "y ~ x1 + x2 + x3 + I(x1**2) + I(x2**2) + I(x3**2) + x1:x2 + x1:x3 + x2:x3"
m = smf.ols(form, data=d).fit()
print("MODELO QUADRÁTICO COMPLETO")
print(m.summary2().tables[1].round(4).to_string())
print(f"\nR² = {m.rsquared:.4f} | R² ajustado = {m.rsquared_adj:.4f}")

# --- Lack of fit: os pontos centrais dão erro puro ---
centrais = d[(d[["x1","x2","x3"]] == 0).all(axis=1)]
ss_puro = ((centrais.y - centrais.y.mean())**2).sum()
gl_puro = len(centrais) - 1
ss_lof = m.ssr - ss_puro
gl_lof = m.df_resid - gl_puro
F_lof = (ss_lof/gl_lof)/(ss_puro/gl_puro)
p_lof = 1 - stats.f.cdf(F_lof, gl_lof, gl_puro)
print(f"\nFALTA DE AJUSTE (lack of fit)")
print(f"   Erro puro: SS = {ss_puro:.4f} ({gl_puro} g.l.)")
print(f"   Falta de ajuste: SS = {ss_lof:.4f} ({gl_lof} g.l.)")
print(f"   F = {F_lof:.3f}, p = {p_lof:.4f}  => "
      f"{'MODELO INADEQUADO' if p_lof < 0.05 else 'modelo adequado (não há falta de ajuste)'}")

# --- Ponto estacionário por álgebra matricial ---
b = m.params
grad_b = np.array([b["x1"], b["x2"], b["x3"]])
B = np.array([
    [b["I(x1 ** 2)"],   b["x1:x2"]/2,     b["x1:x3"]/2],
    [b["x1:x2"]/2,      b["I(x2 ** 2)"],  b["x2:x3"]/2],
    [b["x1:x3"]/2,      b["x2:x3"]/2,     b["I(x3 ** 2)"]]])
xs = -0.5*np.linalg.solve(B, grad_b)
vals = np.linalg.eigvalsh(B)
tipo = ("MÁXIMO" if np.all(vals < 0) else "MÍNIMO" if np.all(vals > 0)
        else "PONTO DE SELA")
print(f"\nANÁLISE CANÓNICA")
print(f"   Ponto estacionário (codificado): "
      f"x1 = {xs[0]:.4f}, x2 = {xs[1]:.4f}, x3 = {xs[2]:.4f}")
print(f"   Valores próprios de B: {np.round(vals, 4)}")
print(f"   Natureza do ponto: {tipo}")
if np.max(np.abs(xs)) > alpha:
    print(f"   ATENÇÃO: o ponto está FORA da região experimental "
          f"(|x| máx = {np.max(np.abs(xs)):.2f} > alpha = {alpha:.2f}).")
    print(f"   Não extrapole: mova o desenho nessa direção e volte a experimentar.")
else:
    yopt = m.predict(pd.DataFrame({"x1":[xs[0]], "x2":[xs[1]], "x3":[xs[2]]}))[0]
    print(f"   Resposta prevista no ótimo: {yopt:.3f}")
    print(f"   Resposta real (verdade)   : {verdade(*xs):.3f}")

# --- Robustez: quão plano é o ótimo? ---
print(f"\nROBUSTEZ DO ÓTIMO — quanto perde por desviar-se dele?")
for delta in [0.1, 0.25, 0.5]:
    perdas = []
    for i in range(3):
        for s in (-delta, delta):
            p = xs.copy(); p[i] += s
            perdas.append(m.predict(pd.DataFrame(
                {"x1":[p[0]], "x2":[p[1]], "x3":[p[2]]}))[0])
    yopt = m.predict(pd.DataFrame({"x1":[xs[0]],"x2":[xs[1]],"x3":[xs[2]]}))[0]
    print(f"   Desvio de ±{delta} em qualquer fator: perda máxima = "
          f"{yopt - min(perdas):.3f} ({(yopt-min(perdas))/yopt:.2%})")
print("   => um ótimo plano tolera variação de processo; um ótimo agudo exige")
print("      controlo apertado. Esta informação vale tanto como a localização.")

# --- Mapa de contorno ---
g1, g2 = np.meshgrid(np.linspace(-alpha, alpha, 90), np.linspace(-alpha, alpha, 90))
grid = pd.DataFrame({"x1": g1.ravel(), "x2": g2.ravel(), "x3": xs[2]})
z = m.predict(grid).values.reshape(g1.shape)
fig, axes = plt.subplots(1, 2, figsize=(13, 4.5))
cs = axes[0].contourf(g1, g2, z, levels=22, cmap="viridis")
axes[0].contour(g1, g2, z, levels=12, colors="white", linewidths=0.5)
plt.colorbar(cs, ax=axes[0], label="resposta")
axes[0].plot(xs[0], xs[1], "r*", ms=18)
axes[0].scatter(d.x1, d.x2, c="white", s=22, edgecolor="black", zorder=5)
axes[0].set_xlabel("x1"); axes[0].set_ylabel("x2")
axes[0].set_title(f"Superfície de resposta (x3 = {xs[2]:.2f})\n★ = ótimo, ● = corridas")
axes[1].scatter(m.fittedvalues, m.resid, s=25)
axes[1].axhline(0, color="r", ls="--"); axes[1].set_xlabel("previsto")
axes[1].set_ylabel("resíduo"); axes[1].set_title("Diagnóstico dos resíduos")
plt.tight_layout(); plt.show()
```

### Multi-response optimization: the desirability function

In practice there's never just one response. There's yield (maximize), defects (minimize), and viscosity (hit a target) — and the three compete.

The **Derringer-Suich desirability function** converts each response to a $[0,1]$ scale and combines them via the geometric mean:

$$D = \left(\prod_{i=1}^{m} d_i^{w_i}\right)^{1/\sum w_i}$$

The geometric mean has an essential property: **if any $d_i = 0$, then $D = 0$**. A solution that completely fails one requirement is rejected by construction, no matter how good it is on the others. An arithmetic mean wouldn't have this property and would allow unacceptable trade-offs.

```py-r
--- python
import numpy as np, pandas as pd
from scipy import optimize
import statsmodels.formula.api as smf

rng2 = np.random.default_rng(31)

# Segunda resposta no mesmo desenho: rugosidade (minimizar)
d["rug"] = (1.8 - 0.35*d.x1 + 0.22*d.x2 + 0.30*d.x3
            + 0.18*d.x1**2 + 0.12*d.x1*d.x2 + rng2.normal(0, 0.05, len(d)))
m_rug = smf.ols("rug ~ x1 + x2 + x3 + I(x1**2) + I(x2**2) + I(x3**2)"
                " + x1:x2 + x1:x3 + x2:x3", data=d).fit()

def d_max(y, lo, hi, s=1.0):     # maximizar
    return np.clip((y-lo)/(hi-lo), 0, 1)**s
def d_min(y, lo, hi, s=1.0):     # minimizar
    return np.clip((hi-y)/(hi-lo), 0, 1)**s

# Preditor rápido: avalia o polinómio diretamente a partir dos coeficientes,
# em vez de reconstruir a fórmula do statsmodels a cada chamada.
def preditor(modelo):
    b = modelo.params
    def f(x):
        x1, x2, x3 = x
        return (b["Intercept"] + b["x1"]*x1 + b["x2"]*x2 + b["x3"]*x3
                + b["I(x1 ** 2)"]*x1**2 + b["I(x2 ** 2)"]*x2**2 + b["I(x3 ** 2)"]*x3**2
                + b["x1:x2"]*x1*x2 + b["x1:x3"]*x1*x3 + b["x2:x3"]*x2*x3)
    return f
f_rend, f_rug = preditor(m), preditor(m_rug)

def desejabilidade(x):
    d1 = d_max(f_rend(x), 80, 90)      # rendimento: maximizar
    d2 = d_min(f_rug(x), 1.2, 2.2)     # rugosidade: minimizar
    return (max(d1, 1e-9) * max(d2, 1e-9))**0.5

lim = [(-alpha, alpha)]*3
best = max((optimize.minimize(lambda x: -desejabilidade(x), x0, bounds=lim)
            for x0 in rng2.uniform(-1, 1, (25, 3))), key=lambda r: -r.fun)
xo = best.x
df_o = pd.DataFrame({"x1":[xo[0]], "x2":[xo[1]], "x3":[xo[2]]})

print("OTIMIZAÇÃO MULTI-RESPOSTA (Derringer-Suich)")
print(f"   Ponto ótimo global (codificado): "
      f"x1 = {xo[0]:.3f}, x2 = {xo[1]:.3f}, x3 = {xo[2]:.3f}")
print(f"   Desejabilidade global D = {-best.fun:.4f}\n")
print(f"   Rendimento previsto = {m.predict(df_o)[0]:.2f}  "
      f"(d = {d_max(m.predict(df_o)[0], 80, 90):.3f})")
print(f"   Rugosidade prevista = {m_rug.predict(df_o)[0]:.3f}  "
      f"(d = {d_min(m_rug.predict(df_o)[0], 1.2, 2.2):.3f})\n")

# Comparar com o ótimo de cada resposta isolada
print("   COMPROMISSO — o ótimo conjunto não é o ótimo de nenhuma resposta:")
so_rend = max((optimize.minimize(lambda x: -f_rend(x), x0, bounds=lim)
               for x0 in rng2.uniform(-1, 1, (15, 3))), key=lambda r: -r.fun)
xr = so_rend.x; dfr = pd.DataFrame({"x1":[xr[0]],"x2":[xr[1]],"x3":[xr[2]]})
print(f"      Só rendimento : x = {np.round(xr,3)} -> rend {m.predict(dfr)[0]:.2f}, "
      f"rug {m_rug.predict(dfr)[0]:.3f}")
print(f"      Compromisso   : x = {np.round(xo,3)} -> rend {m.predict(df_o)[0]:.2f}, "
      f"rug {m_rug.predict(df_o)[0]:.3f}")
print("\n   O ponto de compromisso sacrifica rendimento para cumprir a rugosidade.")
print("   Os pesos e os limites são decisões de NEGÓCIO, não estatísticas —")
print("   e devem ser acordados com o cliente antes da otimização.")
```

### Excel and Power BI (DAX)

Fitting the RSM quadratic model is, just like Chapter 51's multiple regression, feasible via `LINEST` as long as you manually build the columns for the quadratic and interaction terms; the optimization step (finding the surface's optimal point) can then be done with Excel's Solver.

```py-r
--- excel
' 1. Criar colunas x1^2, x2^2, x3^2, x1*x2, x1*x3, x2*x3 a partir dos fatores codificados
' 2. Ajustar com LINEST incluindo todas as colunas (lineares + quadraticas + interacoes)
' 3. Usar o Solver (Dados > Solver) para maximizar/minimizar a celula que calcula
'    y_previsto = intercepto + soma(coef_i * termo_i), variando as celulas dos fatores
'    codificados, sujeito a -1 <= x_i <= 1 (a regiao experimental valida)
--- dax
Y Previsto (RSM) :=
VAR x1 = SELECTEDVALUE ( Simulacao[x1] )
VAR x2 = SELECTEDVALUE ( Simulacao[x2] )
VAR x3 = SELECTEDVALUE ( Simulacao[x3] )
RETURN
    SELECTEDVALUE ( ModeloRSM[Intercepto] )
    + SELECTEDVALUE ( ModeloRSM[b1] ) * x1 + SELECTEDVALUE ( ModeloRSM[b2] ) * x2
    + SELECTEDVALUE ( ModeloRSM[b11] ) * x1 * x1 + SELECTEDVALUE ( ModeloRSM[b12] ) * x1 * x2
```

The DAX measure above is useful as a "what-if simulator" on the dashboard — the user adjusts $x_1, x_2, x_3$ with slicers and watches the predicted $y$ recalculate live — but the coefficients (`ModeloRSM`) and the lack-of-fit validation still come from the fit run in Python/R.

### Common mistakes

1. **Jumping straight to RSM with 8 factors.** A CCD with 8 factors requires more than 80 runs and most factors will be inactive. Screen first.
2. **Not testing for lack of fit.** Without replicated center points there's no pure error and no test is possible. A high $R^2$ doesn't rule out misspecification.
3. **Extrapolating to the stationary point when it falls outside the experimental region.** It's a sign the design is poorly positioned: move the center in that direction (steepest-ascent) and experiment again.
4. **Ignoring the stationary point's nature.** If the eigenvalues have mixed signs, it's a saddle point — there's no maximum or minimum, and "optimizing" there makes no sense. Ridge analysis is the right tool.
5. **Reporting only the optimum's location.** The surface's **flatness** at the optimum is first-order engineering information: it determines how tight process control needs to be.
6. **Not confirming.** After optimizing, run **confirmation runs** at the predicted point. If the result falls outside the prediction interval, the model is wrong.
