## Chapter 52: Logistic Regression: Modeling Conforming / Nonconforming
### The engineering question

*Which combination of process parameters drives the defect probability up — and past what value?*

When the response is binary (good/bad part, test pass/fail, complaint yes/no), linear regression is inadequate: it predicts probabilities outside $[0,1]$, has heteroscedastic residuals by construction, and assumes a linear relationship where the relationship is necessarily sigmoid.

### The model

$$\text{logit}(p) = \ln\!\left(\frac{p}{1-p}\right) = \beta_0 + \beta_1 X_1 + \dots + \beta_p X_p$$

$$p = \frac{1}{1 + e^{-(\beta_0 + \sum \beta_j X_j)}}$$

**How to interpret the coefficients.** $e^{\beta_j}$ is the **odds ratio**: the factor by which the odds of a defect are multiplied for each one-unit increase in $X_j$, holding everything else constant.

| $e^{\beta}$ | Meaning |
|---|---|
| 1.0 | The predictor doesn't change the odds |
| 2.0 | Each unit **doubles** the odds of a defect |
| 0.5 | Each unit **halves** the odds |

**Watch your language.** Odds ratio is **not** relative risk. With small $p$ (which is the case in quality), the two converge; with large $p$, they diverge widely. Saying "doubles the probability of a defect" when the odds ratio is 2 and $p = 0{.}4$ is wrong.

**Typical quality applications:**

- Modeling the probability of nonconformance as a function of process parameters.
- **Attribute agreement analysis**: modeling the probability the inspector classifies correctly as a function of part characteristics — much more informative than a single Kappa.
- Defining **process windows**: finding the parameter region where $P(\text{defect}) < $ target.
- Predicting test failure as a function of manufacturing conditions.

### Worked example: process window in welding

```py-r
--- python
import numpy as np
import pandas as pd
import statsmodels.api as sm
import statsmodels.formula.api as smf
import matplotlib.pyplot as plt
from scipy import stats

rng = np.random.default_rng(31)
n = 900

temp_solda = rng.uniform(230, 275, n)      # °C
tempo = rng.uniform(1.5, 5.0, n)           # s
fluxo = rng.choice(["A", "B"], n, p=[0.6, 0.4])

# Verdade: defeito diminui com temperatura e tempo; fluxo B é pior
eta = 11.2 - 0.052*temp_solda - 0.65*tempo + 0.85*(fluxo == "B")
p_real = 1/(1 + np.exp(-eta))
defeito = rng.binomial(1, p_real)

d = pd.DataFrame({"defeito": defeito, "temp": temp_solda,
                  "tempo": tempo, "fluxo": fluxo})
print(f"n = {n} | taxa de defeito global = {d['defeito'].mean():.2%} "
      f"({d['defeito'].sum()} defeitos)\n")

mod = smf.glm("defeito ~ temp + tempo + C(fluxo)", data=d,
              family=sm.families.Binomial()).fit()
print(mod.summary2().tables[1].round(4).to_string())

# Odds ratios com intervalo de confiança
or_tab = pd.DataFrame({
    "Odds Ratio": np.exp(mod.params),
    "IC 2,5%": np.exp(mod.conf_int()[0]),
    "IC 97,5%": np.exp(mod.conf_int()[1]),
    "p-value": mod.pvalues,
}).round(4)
print("\nODDS RATIOS")
print(or_tab.to_string())
print(f"\nInterpretação:")
print(f"  • Cada +1 °C multiplica as odds de defeito por "
      f"{np.exp(mod.params['temp']):.3f}  "
      f"(-> +10 °C: fator {np.exp(10*mod.params['temp']):.3f})")
print(f"  • Cada +1 s multiplica as odds por {np.exp(mod.params['tempo']):.3f}")
print(f"  • Fluxo B vs A: odds {np.exp(mod.params['C(fluxo)[T.B]']):.2f}x maiores")

# Qualidade do ajuste
ll_null = smf.glm("defeito ~ 1", data=d, family=sm.families.Binomial()).fit().llf
pseudo_r2 = 1 - mod.llf/ll_null
print(f"\nPseudo-R² de McFadden = {pseudo_r2:.3f} "
      f"({'excelente' if pseudo_r2 > 0.4 else 'bom' if pseudo_r2 > 0.2 else 'razoável para eventos raros'})")
print(f"   (McFadden não é comparável com o R² da regressão linear: "
      f"valores de 0,2–0,4 já indicam ajuste forte)")
print(f"Eventos por preditor = {d['defeito'].sum()/3:.1f} "
      f"({'≥10, adequado' if d['defeito'].sum()/3 >= 10 else '<10, estimativas instáveis'})")
print(f"Devianca residual = {mod.deviance:.1f} com {mod.df_resid} g.l. "
      f"(rácio {mod.deviance/mod.df_resid:.3f}; ≈1 indica ajuste adequado)")

# Teste de Hosmer-Lemeshow
def hosmer_lemeshow(y, p, g=10):
    df = pd.DataFrame({"y": y, "p": p}).sort_values("p")
    df["grupo"] = pd.qcut(df["p"].rank(method="first"), g, labels=False)
    ag = df.groupby("grupo").agg(obs=("y","sum"), n=("y","size"), esp=("p","sum"))
    chi = (((ag["obs"]-ag["esp"])**2)/(ag["esp"]*(1-ag["esp"]/ag["n"]))).sum()
    return chi, 1-stats.chi2.cdf(chi, g-2)
hl, hl_p = hosmer_lemeshow(d["defeito"].values, mod.fittedvalues.values)
print(f"Hosmer-Lemeshow: chi2 = {hl:.2f}, p = {hl_p:.3f} "
      f"({'calibração aceitável' if hl_p > 0.05 else 'MÁ CALIBRAÇÃO'})")

# --- A pergunta de engenharia: qual a janela de processo? ---
ALVO = 0.01      # queremos P(defeito) < 1%
print(f"\nJANELA DE PROCESSO para P(defeito) < {ALVO:.0%}, fluxo A:")
for t in [2.0, 3.0, 4.0, 5.0]:
    b = mod.params
    # resolver eta = logit(alvo) para temp
    temp_min = (np.log(ALVO/(1-ALVO)) - b["Intercept"] - b["tempo"]*t) / b["temp"]
    dentro = 230 <= temp_min <= 275
    print(f"   tempo = {t:.1f} s  ->  temperatura mínima = {temp_min:6.1f} °C"
          f"  {'' if dentro else '  (fora do domínio estudado — extrapolação)'}")

# Mapa de contorno
tt, pp = np.meshgrid(np.linspace(230, 275, 120), np.linspace(1.5, 5.0, 120))
grid = pd.DataFrame({"temp": tt.ravel(), "tempo": pp.ravel(), "fluxo": "A"})
z = mod.predict(grid).values.reshape(tt.shape)

fig, axes = plt.subplots(1, 2, figsize=(13, 4.5))
cs = axes[0].contourf(tt, pp, z, levels=20, cmap="RdYlGn_r")
cl = axes[0].contour(tt, pp, z, levels=[0.01, 0.05, 0.10], colors="black", linewidths=1.5)
axes[0].clabel(cl, fmt="%.2f")
plt.colorbar(cs, ax=axes[0], label="P(defeito)")
axes[0].set_xlabel("temperatura (°C)"); axes[0].set_ylabel("tempo (s)")
axes[0].set_title("Janela de processo — fluxo A\n(linhas: iso-probabilidade de defeito)")

# Curva ROC (calculada sem dependências externas)
def roc(y, score):
    o = np.argsort(-np.asarray(score)); y = np.asarray(y)[o]
    tpr = np.concatenate([[0], np.cumsum(y)/max(y.sum(), 1)])
    fpr = np.concatenate([[0], np.cumsum(1-y)/max((1-y).sum(), 1)])
    return fpr, tpr, np.trapezoid(tpr, fpr) if hasattr(np, "trapezoid") else np.trapz(tpr, fpr)
fpr, tpr, auc = roc(d["defeito"].values, mod.fittedvalues.values)
axes[1].plot(fpr, tpr, lw=2); axes[1].plot([0,1],[0,1],"k--", lw=1)
axes[1].set_xlabel("1 - especificidade"); axes[1].set_ylabel("sensibilidade")
axes[1].set_title(f"Curva ROC — AUC = {auc:.3f}")
plt.tight_layout(); plt.show()
```

```py-r
--- r
set.seed(31)
n <- 900
temp <- runif(n, 230, 275); tempo <- runif(n, 1.5, 5.0)
fluxo <- sample(c("A","B"), n, TRUE, prob = c(0.6, 0.4))
eta <- 11.2 - 0.052*temp - 0.65*tempo + 0.85*(fluxo == "B")
defeito <- rbinom(n, 1, 1/(1+exp(-eta)))
d <- data.frame(defeito, temp, tempo, fluxo = factor(fluxo))

mod <- glm(defeito ~ temp + tempo + fluxo, data = d, family = binomial)
print(summary(mod)$coefficients)

or_ic <- cbind(OR = exp(coef(mod)), exp(confint.default(mod)))
cat("\nOdds ratios com IC 95%:\n"); print(round(or_ic, 4))

ll0 <- glm(defeito ~ 1, data = d, family = binomial)$deviance
cat(sprintf("\nPseudo-R2 McFadden = %.3f\n", 1 - mod$deviance/ll0))
cat(sprintf("Devianca/gl = %.3f\n", mod$deviance/mod$df.residual))

alvo <- 0.01
for (t in c(2, 3, 4, 5)) {
  b <- coef(mod)
  tmin <- (log(alvo/(1-alvo)) - b[1] - b["tempo"]*t) / b["temp"]
  cat(sprintf("tempo = %.1f s -> temperatura minima = %.1f C\n", t, tmin))
}
```

**Engineering reading.** The model delivers exactly what engineering needs: a **process-window map**. The iso-probability lines say, for each combination of temperature and time, the expected defect rate — letting you choose the operating point with margin, instead of operating at the edge.

Also note the response's structure: the safe region isn't a rectangle. There's a **trade-off** between temperature and time — less temperature is offset by more time. A control plan that sets independent limits for each parameter ignores this trade-off and ends up simultaneously too restrictive in one zone and too permissive in another.

**On AUC.** The area under the ROC curve measures discrimination ability. But be careful: in quality, with low defect rates, **AUC can be high and the model can still be useless in practice**, because almost every prediction is close to zero. Calibration (Hosmer-Lemeshow) matters more than discrimination when the goal is defining process windows rather than classifying parts.

### Excel and Power BI (DAX)

Excel **doesn't have** a native logistic regression function (there's no LINEST equivalent for MLE with a logit link function). The classic workaround before dedicated statistical software was to build the log-likelihood in a helper column and maximize it with Solver — it works, but it's fragile and doesn't scale past 2-3 predictors; it isn't recommended for production use.

```py-r
--- dax
Probabilidade Prevista :=
VAR b0 = SELECTEDVALUE ( ModeloLogistico[Intercepto] )
VAR b_temp = SELECTEDVALUE ( ModeloLogistico[Coef_Temp] )
VAR b_tempo = SELECTEDVALUE ( ModeloLogistico[Coef_Tempo] )
VAR eta = b0 + b_temp * SELECTEDVALUE ( Solda[Temp] ) + b_tempo * SELECTEDVALUE ( Solda[Tempo] )
RETURN DIVIDE ( 1, 1 + EXP ( -eta ) )

Classificacao Risco :=
SWITCH ( TRUE,
    [Probabilidade Prevista] >= 0.10, "Alto risco de defeito",
    [Probabilidade Prevista] >= 0.03, "Atenção",
    "Dentro da janela segura" )
```

Here, Power BI only consumes coefficients **already fitted** in Python/R (a `ModeloLogistico` table) and recomputes the sigmoid formula for new temperature/time combinations in real time on the dashboard — useful for an operator to check the defect probability before operating outside the tested window, but the model fitting stays exclusively in Python/R.

### Common mistakes

1. **Using linear regression on a binary response.** It predicts negative probabilities.
2. **Interpreting odds ratio as relative risk.** Only approximately valid with small $p$.
3. **Complete separation.** If a predictor perfectly separates the classes, the coefficients diverge to infinity and the standard errors explode. Symptom: huge coefficients with huge standard errors. Fix: penalized regression (Firth or ridge).
4. **Too few events per predictor.** The rule of thumb requires ≥ 10 events (the minority class) per predictor. With 12 defects, you can't estimate 5 coefficients.
5. **Ignoring hierarchical structure.** If the parts come from lots, there's within-lot correlation. That's a case for mixed models (a later chapter) or GEE.
6. **Defaulting to a 0.5 cutoff.** In quality, with unbalanced classes, the cutoff should be derived from the relative costs of false positives and false negatives.
