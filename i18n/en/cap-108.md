## Chapter 108: Data Engineering for Quality: ETL, Pipelines and Lineage
### The engineering question

*If I'm asked, two years from now, to reproduce this exact report, can I?*

If the answer is no, the data process does not meet the **objective evidence** requirements that ISO 9001 itself imposes on the rest of the quality system. A hand-manipulated Excel file is not reproducible evidence — it's a result with no process behind it.

### ETL and ELT

**ETL** (*Extract, Transform, Load*) — transform before loading. Traditional, suited when the destination is a structured data warehouse and the volume is moderate.

**ELT** (*Extract, Load, Transform*) — load raw and transform at the destination. Modern, suited when storage is cheap and you want to preserve the original data.

> **For quality, ELT has a decisive advantage: it preserves the raw data.** If, two years from now, it turns out the outlier-exclusion rule was wrong, ELT lets you reprocess; with ETL, the original information has already been destroyed.

### The layers of a pipeline (medallion)

| Layer | Content | Rule |
|---|---|---|
| **Bronze** (raw) | Faithful copy of the source, unaltered | **Never edited.** Immutable, timestamped |
| **Silver** (clean) | Corrected types, duplicates removed, keys normalized | Every rule applied is **logged** |
| **Gold** (analytics) | Aggregated tables ready for consumption | This is what feeds dashboards and reports |

The golden rule of a quality pipeline: **no transformation without a record of what changed and why.**

### Idempotency and reprocessing

A pipeline is **idempotent** if running it twice produces the same result as running it once. Without that, a re-run after a failure duplicates records — and the supplier's PPM duplicates along with them.

How to guarantee it:
- Natural keys with `MERGE`/`UPSERT` instead of blind `INSERT`.
- Partitions replaced wholesale (reprocessing day 12 deletes and rewrites day 12).
- Watermarks to know how far processing has already reached.

### Data lineage

Lineage is the record of **where each number came from and what transformations it went through**. It is the data-world equivalent of lot traceability — and it serves the same function in an audit.

Questions that lineage answers, and that go unanswered without it:

- Does this PPM include or exclude rework?
- Which rule decided that these 14 measurements were invalid?
- Was June's report calculated with the same definition as July's?
- If the MES changes time zone, which indicators are affected?

### Worked example: an auditable pipeline

```py-r
--- python
import pandas as pd
import numpy as np
import hashlib, json
from datetime import datetime, timezone

rng = np.random.default_rng(11)

# ---------- BRONZE: dados brutos, tal como chegam do MES ----------
n = 500
bruto = pd.DataFrame({
    "id_peca":   [f"P{i:05d}" for i in range(n)],
    "timestamp": pd.date_range("2026-06-01", periods=n, freq="17min").astype(str),
    "maquina":   rng.choice(["M1", "m1", "M2", "M-2", "M3"], n),   # inconsistente!
    "valor":     rng.normal(10.0, 0.04, n).round(4).astype(str),   # texto!
    "operador":  rng.choice(["Ana", "ana ", "Bruno", "BRUNO", None], n),
})
# poluição típica de dados reais
bruto.loc[rng.choice(n, 12, replace=False), "valor"] = ""          # em falta
bruto.loc[rng.choice(n, 5, replace=False), "valor"] = "-999"       # sentinela
bruto.loc[rng.choice(n, 8, replace=False), "valor"] = "10,05"      # vírgula decimal
dup = bruto.sample(15, random_state=1)
bruto = pd.concat([bruto, dup], ignore_index=True)                 # duplicados

print("CAMADA BRONZE (bruta, imutável)")
print(f"   {len(bruto)} registos | hash = "
      f"{hashlib.sha256(bruto.to_csv(index=False).encode()).hexdigest()[:16]}")
print(bruto.head(4).to_string(index=False))

# ---------- PRATA: limpeza COM REGISTO de cada regra ----------
registo = []
def regra(nome, df_antes, df_depois, detalhe=""):
    registo.append({
        "regra": nome,
        "registos_antes": len(df_antes),
        "registos_depois": len(df_depois),
        "afetados": len(df_antes) - len(df_depois),
        "detalhe": detalhe,
        "executado_em": datetime.now(timezone.utc).isoformat(timespec="seconds"),
    })

d = bruto.copy()

a = d.copy(); d = d.drop_duplicates(subset=["id_peca"], keep="first")
regra("desduplicar por id_peca", a, d, "mantém o primeiro registo")

d["maquina"] = (d["maquina"].str.upper().str.replace("-", "", regex=False))
regra("normalizar código de máquina", d, d,
      f"níveis distintos: {bruto.maquina.nunique()} -> {d.maquina.nunique()}")

d["operador"] = d["operador"].str.strip().str.title()
regra("normalizar nome de operador", d, d,
      f"níveis: {bruto.operador.nunique()} -> {d.operador.nunique()}")

d["valor"] = pd.to_numeric(d["valor"].str.replace(",", ".", regex=False),
                           errors="coerce")
n_nulos = int(d["valor"].isna().sum())
regra("converter valor para numérico", d, d,
      f"{n_nulos} valores não convertíveis -> NaN (preservados, não apagados)")

a = d.copy()
sentinelas = d["valor"] <= -900
d.loc[sentinelas, "valor"] = np.nan
regra("marcar sentinelas (-999) como em falta", a, d,
      f"{int(sentinelas.sum())} registos. NUNCA tratar -999 como medição real")

d["timestamp"] = pd.to_datetime(d["timestamp"])
d["data"] = d["timestamp"].dt.date
regra("tipificar timestamp", d, d, "ISO-8601, UTC assumido")

print("\n\nCAMADA PRATA — registo de transformações (a LINHAGEM)")
log = pd.DataFrame(registo)
print(log[["regra", "registos_antes", "registos_depois", "afetados", "detalhe"]]
      .to_string(index=False))

# ---------- Regra crítica: em falta NÃO é zero ----------
print(f"\n   Registos com medição em falta: {int(d['valor'].isna().sum())} "
      f"({d['valor'].isna().mean():.1%})")
print("   Estes registos são MANTIDOS com valor nulo, e não apagados nem")
print("   substituídos por zero. Apagar esconde um problema de recolha;")
print("   pôr zero corrompe todas as médias a jusante.")

# ---------- OURO: tabela analítica ----------
ouro = (d.dropna(subset=["valor"])
          .groupby(["data", "maquina"])
          .agg(n=("valor", "size"), media=("valor", "mean"),
               sd=("valor", "std"), minimo=("valor", "min"), maximo=("valor", "max"))
          .reset_index())
ouro["completude"] = ouro["n"] / d.groupby(["data", "maquina"]).size().values
print(f"\n\nCAMADA OURO — {len(ouro)} linhas agregadas")
print(ouro.head(6).round(4).to_string(index=False))

# ---------- Manifesto de execução: o que torna isto auditável ----------
manifesto = {
    "pipeline": "qualidade_dimensional",
    "versao": "1.3.0",
    "executado_em": datetime.now(timezone.utc).isoformat(timespec="seconds"),
    "fonte": "MES / tabela medicoes_brutas",
    "hash_entrada": hashlib.sha256(bruto.to_csv(index=False).encode()).hexdigest()[:16],
    "hash_saida": hashlib.sha256(ouro.to_csv(index=False).encode()).hexdigest()[:16],
    "registos_entrada": len(bruto),
    "registos_saida_prata": len(d),
    "registos_descartados": len(bruto) - len(d),
    "medicoes_em_falta": int(d["valor"].isna().sum()),
    "regras_aplicadas": [r["regra"] for r in registo],
}
print("\n\nMANIFESTO DE EXECUÇÃO (guardar com o resultado)")
print(json.dumps(manifesto, indent=2, ensure_ascii=False))
print("\nÉ este objeto que responde, numa auditoria, à pergunta")
print("'como é que chegou a este número?' — e que permite reproduzir o relatório.")
```

**Engineering takeaway.** What distinguishes this pipeline from a manual Excel cleanup isn't the result: it's the **log**. Every rule was documented with how many records it affected and why, and the manifest links input and output by hash.

Three decisions deserve a closer look:

**The `-999` sentinel value.** This is the most common and most destructive trap in industrial data. Legacy systems use `-999`, `9999` or `0` to mean "not measured." Treating them as real measurements destroys means, standard deviations and capability — and the error is silent.

**Missing ≠ zero ≠ deleted.** Keeping the record with a null value preserves the information that the part existed and was not measured — which is exactly what a completeness audit needs to find.

**Normalizing `M1`/`m1`/`M-2`.** Before normalization, stratifying by machine would produce 5 groups where only 3 exist, and each group would have less data than it should. This kind of error produces no error message at all: it produces wrong conclusions.

### Common mistakes

1. **Transforming the source in place.** Never. The bronze layer is immutable.
2. **A non-idempotent pipeline.** Re-running it duplicates data.
3. **Imputing missing values without declaring it.** If you impute, log the method and keep an indicator column.
4. **Time zones.** A night shift crosses midnight; if the MES logs in UTC and the ERP in local time, shift-N data ends up split across two days. This error is common and hard to detect.
5. **No versioning of business rules.** If the definition of "defect" changed in March, the series before and after are not comparable — and the dashboard will show an "improvement" that is really just a change in definition.
6. **Connecting Power BI directly to the production database.** It loads the operational system and leaves no layer where transformations can be documented.
