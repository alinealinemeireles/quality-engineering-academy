## Chapter 109: Data Quality: Applying Quality to the Data Itself
### The engineering question

*We apply statistical control to the process. Do we apply anything to the process that produces our data?*

In most organizations, no. Data is treated as guaranteed-quality raw material — precisely the assumption that quality engineering rejects in every other context.

**A piece of data is the output of a process**, with suppliers (source systems), operations (collection, transformation), quality characteristics and failure modes. It deserves a control plan.

### The six dimensions of data quality

| Dimension | Question | How to measure it | Typical failure in quality |
|---|---|---|---|
| **Completeness** | Is anything missing? | % of fields filled versus expected | Parts produced with no inspection record |
| **Accuracy** | Does it match reality? | Cross-check against an independent source or physical recount | Scrap count diverges from stock |
| **Consistency** | Do the systems agree? | Reconciliation between ERP, MES and LIMS | Lot quantity differs between systems |
| **Timeliness** | Does it arrive in time to decide? | Delay between occurrence and availability | Defect logged 3 days later |
| **Uniqueness** | Are there duplicates? | Count of repeated keys | The same NC entered twice |
| **Validity** | Does it respect the rules? | % that passes domain and range rules | Negative diameter; date in the future |

**The most expensive dimension is accuracy**, because it requires an independent source of truth. The other five can be checked within the system itself; accuracy requires going to the shop floor to count.

### Worked example: an automated data-quality profile

```py-r
--- python
import pandas as pd
import numpy as np

rng = np.random.default_rng(2026)
n = 1500

d = pd.DataFrame({
    "id_registo": range(1, n+1),
    "id_peca":    [f"P{i:05d}" for i in rng.integers(1, n, n)],   # gera duplicados
    "data_producao": pd.to_datetime("2026-06-01") + pd.to_timedelta(
                        rng.integers(0, 90, n), unit="D"),
    "data_inspecao":  pd.to_datetime("2026-06-01") + pd.to_timedelta(
                        rng.integers(0, 95, n), unit="D"),
    "diametro":   rng.normal(10.0, 0.05, n).round(4),
    "operador":   rng.choice(["Ana", "Bruno", "Carla", None], n, p=[.3,.3,.3,.1]),
    "turno":      rng.choice(["M","T","N","X",""], n, p=[.32,.32,.31,.03,.02]),
    "resultado":  rng.choice(["OK","NOK"], n, p=[.94,.06]),
})
# injetar problemas realistas
d.loc[rng.choice(n, 45, replace=False), "diametro"] = np.nan
d.loc[rng.choice(n, 9,  replace=False), "diametro"] = -999
d.loc[rng.choice(n, 6,  replace=False), "diametro"] = 0.0
d.loc[rng.choice(n, 20, replace=False), "data_producao"] = pd.NaT

TURNOS_VALIDOS = {"M","T","N"}
LSL, USL = 9.85, 10.15
LIMITE_FISICO = (5.0, 15.0)

resultados = []
def check(dim, regra, mask_falha, critico=False):
    resultados.append({"Dimensão": dim, "Regra": regra,
                       "Registos com falha": int(mask_falha.sum()),
                       "% falha": round(100*mask_falha.mean(), 2),
                       "Crítico": "SIM" if critico else ""})

# --- COMPLETUDE ---
for col in ["diametro", "operador", "data_producao"]:
    check("Completude", f"{col} preenchido", d[col].isna(), critico=(col=="diametro"))

# --- VALIDADE ---
check("Validade", "turno em {M,T,N}", ~d["turno"].isin(TURNOS_VALIDOS), critico=True)
check("Validade", f"diâmetro dentro do plausível físico {LIMITE_FISICO}",
      d["diametro"].notna() &
      ((d["diametro"] < LIMITE_FISICO[0]) | (d["diametro"] > LIMITE_FISICO[1])),
      critico=True)
check("Validade", "diâmetro exatamente zero (suspeito)",
      d["diametro"] == 0.0, critico=True)
check("Validade", "resultado em {OK,NOK}", ~d["resultado"].isin({"OK","NOK"}))

# --- CONSISTÊNCIA ---
check("Consistência", "inspeção não anterior à produção",
      d["data_inspecao"].notna() & d["data_producao"].notna() &
      (d["data_inspecao"] < d["data_producao"]), critico=True)
fora_spec = d["diametro"].notna() & ((d["diametro"] < LSL) | (d["diametro"] > USL))
check("Consistência", "resultado 'OK' mas medição fora de especificação",
      fora_spec & (d["resultado"] == "OK"), critico=True)

# --- UNICIDADE ---
check("Unicidade", "id_peca sem duplicados", d["id_peca"].duplicated(keep=False))

# --- ATUALIDADE ---
atraso = (d["data_inspecao"] - d["data_producao"]).dt.days
check("Atualidade", "inspeção até 3 dias após produção", atraso > 3)

perfil = pd.DataFrame(resultados)
print("PERFIL DE QUALIDADE DE DADOS")
print(perfil.to_string(index=False))

criticos = perfil[perfil["Crítico"] == "SIM"]["Registos com falha"].sum()
print(f"\nTotal de falhas em regras CRÍTICAS: {criticos}")
print(f"Registos totalmente limpos: "
      f"{int((~d.isna().any(axis=1) & d['turno'].isin(TURNOS_VALIDOS)).sum())}"
      f" de {n}")

# --- Índice global e carta de controlo da qualidade dos dados ---
print("\n\nSPC APLICADO À QUALIDADE DOS DADOS")
d["semana"] = d["data_producao"].dt.isocalendar().week
por_semana = d.groupby("semana").apply(
    lambda g: pd.Series({
        "n": len(g),
        "pct_completo": 100*(1 - g["diametro"].isna().mean()),
        "pct_turno_valido": 100*g["turno"].isin(TURNOS_VALIDOS).mean(),
    }), include_groups=False).reset_index()

pbar = por_semana["pct_completo"].mean()/100
por_semana["LSC"] = 100*(pbar + 3*np.sqrt(pbar*(1-pbar)/por_semana["n"]))
por_semana["LIC"] = 100*np.maximum(0, pbar - 3*np.sqrt(pbar*(1-pbar)/por_semana["n"]))
por_semana["Sinal"] = np.where(
    (por_semana["pct_completo"] > por_semana["LSC"]) |
    (por_semana["pct_completo"] < por_semana["LIC"]), "<<< FORA", "")
print(por_semana.round(2).to_string(index=False))
print("\nA completude dos dados é ela própria uma característica de qualidade,")
print("com processo, variação comum e causas especiais. Merece uma carta p.")
```

### The data control plan

If data is a process, it should have a control plan with the same structure as any other:

| Element | As applied to data |
|---|---|
| **Characteristic** | Completeness of the `diameter` field |
| **Specification** | ≥ 99% of records filled |
| **Measurement method** | Automated daily query |
| **Frequency** | Daily |
| **Control method** | p-chart of the completion percentage |
| **Reaction plan** | < 97% → notify the line owner; < 90% → suspend the dashboard and investigate |
| **Owner** | Named data owner |

> **The reaction plan is the element that almost never exists.** Most organizations have data-quality indicators and no defined consequence when they degrade. Without a reaction plan, the indicator is decorative — exactly like a control chart nobody looks at.

### Common mistakes

1. **Assuming the system's data is correct because it came from the system.** IT guarantees the number was stored; it does not guarantee it matches reality.
2. **Imputing silently.** Filling missing values with the mean biases the variance downward and artificially improves capability.
3. **Deleting problematic rows.** You lose the information that a collection problem occurred.
4. **Checking data quality only when a result looks strange.** That's checking by exception, and it fails precisely in the cases where the wrong result looks plausible.
5. **Not having a data owner.** With no named owner, data-quality problems belong to no one.
6. **Confusing validity with accuracy.** A diameter of 10.02 mm is valid (it's within range) and can still be wrong (the part actually measures 10.08 mm). Validity can be checked by itself; accuracy requires going out to measure.
