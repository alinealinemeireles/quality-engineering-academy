## Chapter 72: Capability for Non-Normal and Attribute Data
### The engineering question

*Is my characteristic physically capable of being normal?*

Ask this question **before** testing for normality. Many quality characteristics can't be normal for physical reasons, and no sample size will change that:

| Characteristic | Why it isn't normal | Typical distribution |
|---|---|---|
| Flatness, runout, roundness (**form GD&T**) | Bounded below at zero; right-skewed | Weibull, lognormal, half-normal |
| Roughness Ra | Same | Lognormal |
| Time to failure, cycle time | Positive, skewed | Weibull, lognormal, exponential |
| Contamination, impurities (ppm) | Bounded at zero, long tail | Lognormal, gamma |
| Tightening torque with a stop | Truncated above | Truncated distribution |
| Concentricity | Radial, always positive | Rayleigh |

> For these characteristics, **testing for normality and "fixing" outliers is the mistake**, not the solution. The skew is the process's correct behavior.

### The three approaches

**A) Transformation (Box-Cox or Johnson)**

Transform $y = f(x)$, check $y$'s normality, calculate the indices in the transformed space with the specification limits also transformed.

$$y = \begin{cases} \dfrac{x^\lambda - 1}{\lambda} & \lambda \neq 0 \\[6pt] \ln x & \lambda = 0 \end{cases}$$

*Advantage:* simple, available in any software.
*Disadvantage:* $C_{pk}$ in the transformed space **has no direct physical interpretation**. And if the process isn't stable, the transformation masks that instead of revealing it.

**The Johnson alternative.** When a single power transformation isn't enough to bring the distribution close to normal — typical of processes with more complex behavior, pronounced natural limits, or very long tails — the Johnson system offers a more flexible alternative. Instead of a single power parameter, it uses three families of functions (bounded — $S_B$ —, unbounded — $S_U$ —, and lognormal — $S_L$) that cover a wider range of distribution shapes, including logistic and hyperbolic transformations. Choosing between the families and their parameters is normally done by dedicated statistical software (Minitab, for example, automatically fits the best Johnson family); the principle of use is identical to Box-Cox — transform, check normality in the transformed space, calculate the indices there, and remember the resulting value has no direct physical interpretation in the original units.

**B) Percentile method (ISO/Pearson)** — recommended

Fit the appropriate distribution to the data and use the actual percentiles instead of $\pm 3\sigma$:

$$P_{pk} = \min\left(\frac{USL - X_{0.50}}{X_{0.99865} - X_{0.50}},\; \frac{X_{0.50} - LSL}{X_{0.50} - X_{0.00135}}\right)$$

For the normal distribution, this formula reduces exactly to the classic $P_{pk}$ — which makes it a generalization, not an alternative.

*Advantage:* keeps the interpretation in real units and links directly to ppm.
*Disadvantage:* requires choosing and validating the distribution, and is sensitive to that choice in the tails.

**C) Report ppm directly**

The most honest approach, and the easiest to communicate to the customer. Fit the distribution, calculate $P(X > USL) + P(X < LSL)$, and report in ppm. If the customer requires an index, convert:

$$C_{pk,\text{equivalent}} = \frac{Z_{\text{bench}}}{3} \quad\text{where}\quad Z_{\text{bench}} = \Phi^{-1}(1 - p_{\text{total}})$$

### Worked example: flatness — the classic case

```py-r
--- python
import numpy as np
import pandas as pd
from scipy import stats
import matplotlib.pyplot as plt

rng = np.random.default_rng(77)

# Planeza (mm): só limite superior, distribuição naturalmente assimétrica
USL = 0.080
dados = stats.weibull_min.rvs(1.9, loc=0.0, scale=0.030, size=250, random_state=77)

print(f"n = {len(dados)} | média = {dados.mean():.4f} | mediana = {np.median(dados):.4f} "
      f"| desvio-padrão = {dados.std(ddof=1):.4f}")
print(f"Assimetria = {stats.skew(dados):.3f} | Curtose = {stats.kurtosis(dados):.3f}")
W, p = stats.shapiro(dados)
print(f"Shapiro-Wilk: W = {W:.4f}, p = {p:.2e} => "
      f"{'normalidade REJEITADA' if p < 0.05 else 'compatível com normal'}\n")

defeitos_obs = (dados > USL).mean()
print(f"Fração fora de especificação OBSERVADA: {defeitos_obs*1e6:,.0f} ppm "
      f"({(dados > USL).sum()} de {len(dados)})\n")
print("="*68)

# ---------- ABORDAGEM ERRADA: assumir normalidade ----------
mu, sd = dados.mean(), dados.std(ddof=1)
Ppu_norm = (USL - mu) / (3*sd)
ppm_norm = stats.norm.sf(USL, mu, sd) * 1e6
print("1) ERRADO — assumir normalidade:")
print(f"   Ppu = {Ppu_norm:.3f}   |   ppm previsto = {ppm_norm:,.0f}")
print(f"   Erro face ao observado: fator de {defeitos_obs*1e6/max(ppm_norm,1e-9):,.0f}x\n")

# ---------- A) Transformação de Box-Cox ----------
transf, lam = stats.boxcox(dados)
USL_t = (USL**lam - 1)/lam if lam != 0 else np.log(USL)
mu_t, sd_t = transf.mean(), transf.std(ddof=1)
Ppu_bc = (USL_t - mu_t) / (3*sd_t)
ppm_bc = stats.norm.sf(USL_t, mu_t, sd_t) * 1e6
W2, p2 = stats.shapiro(transf)
print(f"2) Transformação de Box-Cox (lambda = {lam:.3f}):")
print(f"   Normalidade após transformar: p = {p2:.3f} "
      f"({'OK' if p2 > 0.05 else 'ainda não normal'})")
print(f"   Ppu(transformado) = {Ppu_bc:.3f}  |  ppm previsto = {ppm_bc:,.0f}\n")

# ---------- B) Método dos percentis com Weibull ----------
c, loc, scale = stats.weibull_min.fit(dados, floc=0)
X_50    = stats.weibull_min.ppf(0.50,    c, loc, scale)
X_99865 = stats.weibull_min.ppf(0.99865, c, loc, scale)
Ppu_perc = (USL - X_50) / (X_99865 - X_50)
ppm_wb = stats.weibull_min.sf(USL, c, loc, scale) * 1e6
ks, p_ks = stats.kstest(dados, 'weibull_min', args=(c, loc, scale))
print(f"3) Método dos percentis — Weibull (forma={c:.3f}, escala={scale:.4f}):")
print(f"   Aderência (KS): D = {ks:.4f}, p = {p_ks:.3f} "
      f"({'ajuste adequado' if p_ks > 0.05 else 'ajuste duvidoso'})")
print(f"   X(0,5) = {X_50:.4f} | X(0,99865) = {X_99865:.4f}")
print(f"   Ppu(percentis) = {Ppu_perc:.3f}  |  ppm previsto = {ppm_wb:,.0f}\n")

# ---------- Comparação de distribuições candidatas ----------
print("4) Qual distribuição? Comparação por AIC:")
cands = {
    "Weibull":     (stats.weibull_min, dict(floc=0)),
    "Lognormal":   (stats.lognorm,     dict(floc=0)),
    "Gama":        (stats.gamma,       dict(floc=0)),
    "Normal":      (stats.norm,        {}),
}
res = []
for nome, (dist, kw) in cands.items():
    par = dist.fit(dados, **kw)
    ll = dist.logpdf(dados, *par).sum()
    k = len(par) - len(kw)
    aic = 2*k - 2*ll
    ppm = dist.sf(USL, *par)*1e6
    D, pv = stats.kstest(dados, dist.name, args=par)
    res.append({"Distribuição": nome, "AIC": round(aic,1), "KS p-value": round(pv,4),
                "ppm previsto": round(ppm)})
cmp = pd.DataFrame(res).sort_values("AIC")
cmp["ppm observado"] = round(defeitos_obs*1e6)
print(cmp.to_string(index=False))

# ---------- C) Z-bench ----------
p_total = stats.weibull_min.sf(USL, c, loc, scale)
z_bench = stats.norm.isf(p_total)
print(f"\n5) Reportar em ppm e Z-bench (recomendado):")
print(f"   p(fora) = {p_total:.6f}  ->  {p_total*1e6:,.0f} ppm")
print(f"   Z-bench = {z_bench:.3f}  ->  Cpk equivalente = {z_bench/3:.3f}")

print("\n" + "="*68)
print("RESUMO — o mesmo processo, quatro respostas:")
print(pd.DataFrame([
    ("Normal (incorreto)",        round(Ppu_norm,3),  f"{ppm_norm:,.0f}"),
    ("Box-Cox",                   round(Ppu_bc,3),    f"{ppm_bc:,.0f}"),
    ("Percentis (Weibull)",       round(Ppu_perc,3),  f"{ppm_wb:,.0f}"),
    ("Observado na amostra",      "-",                f"{defeitos_obs*1e6:,.0f}"),
], columns=["Método", "Ppu", "ppm"]).to_string(index=False))

fig, axes = plt.subplots(1, 2, figsize=(13, 4))
axes[0].hist(dados, bins=30, density=True, alpha=0.6, color="#6fa8be", edgecolor="white")
xs = np.linspace(0, max(dados.max(), USL)*1.15, 400)
axes[0].plot(xs, stats.weibull_min.pdf(xs, c, loc, scale), lw=2, label="Weibull ajustada")
axes[0].plot(xs, stats.norm.pdf(xs, mu, sd), lw=2, ls="--", color="crimson",
             label="Normal (inadequada)")
axes[0].axvline(USL, color="red", lw=2); axes[0].text(USL, axes[0].get_ylim()[1]*0.9, " USL")
axes[0].legend(fontsize=8); axes[0].set_title("Planeza — a normal prevê valores negativos")
stats.probplot(dados, dist=stats.weibull_min(c, loc, scale), plot=axes[1])
axes[1].set_title("Gráfico de probabilidade — Weibull")
plt.tight_layout(); plt.show()
```

**Engineering reading.** The three approaches give different indices for the **same process**. What changes isn't the process — it's the model imposed on it.

The critical point is in comparing predicted ppm against observed ppm. The normality assumption grossly underestimates the out-of-spec fraction, because the real right tail is much heavier than the normal allows. A capability report based on that assumption can declare capable a process that produces measurable scrap.

And notice the geometric absurdity: the fitted normal assigns non-negligible probability to **negative flatness**, which is physically impossible.

### Capability for attribute data

When the characteristic is binary (conforming/nonconforming), there's no $C_{pk}$. Two useful quantities exist:

**Sigma level from DPMO.** Converts the defect rate into an equivalent Z:

$$Z_{\text{long-term}} = \Phi^{-1}\left(1 - \frac{\text{DPMO}}{10^6}\right) \qquad Z_{\text{short-term}} = Z_{\text{long-term}} + 1.5$$

Adding 1.5 is the Six Sigma **convention** for the typical long-term shift — it isn't a mathematical property. Always state which one you're reporting.

**Confidence interval of the proportion.** Much more important than the point estimate. With 0 defects in 300 parts, the estimated proportion is 0% — but the 95%-confidence upper bound is about 1%, which corresponds to 10,000 ppm. "Zero defects in the sample" and "capable process" aren't the same statement.

```py-r
--- python
import numpy as np
from scipy import stats
import pandas as pd

def capability_atributos(defeitos, n, oportunidades_por_unidade=1):
    dpu = defeitos / n
    dpo = defeitos / (n * oportunidades_por_unidade)
    dpmo = dpo * 1e6
    p = defeitos / n
    # Intervalo de confiança de Wilson (robusto para p pequeno)
    z = 1.96
    den = 1 + z**2/n
    centro = (p + z**2/(2*n)) / den
    metade = z*np.sqrt(p*(1-p)/n + z**2/(4*n**2)) / den
    lo, hi = max(0, centro-metade), min(1, centro+metade)
    z_lt = stats.norm.isf(dpo) if 0 < dpo < 1 else np.nan
    return {"n": n, "Defeitos": defeitos, "DPU": round(dpu,5),
            "DPMO": round(dpmo,1),
            "IC95% da proporção": f"[{lo*1e6:,.0f} ; {hi*1e6:,.0f}] ppm",
            "Z longo prazo": round(z_lt,2) if not np.isnan(z_lt) else "-",
            "Z curto prazo (+1,5)": round(z_lt+1.5,2) if not np.isnan(z_lt) else "-"}

casos = [(0, 300, 1), (0, 3000, 1), (3, 1200, 1), (12, 5000, 1), (2, 900, 1)]
print(pd.DataFrame([capability_atributos(*c) for c in casos]).to_string(index=False))

print("\nRepare nas duas primeiras linhas: ZERO defeitos em ambas,")
print("mas o limite superior do intervalo de confiança difere por um fator de 10.")
print("A afirmação 'não encontrámos defeitos' depende inteiramente de n.")

# Quantas peças são precisas para demonstrar um nível de qualidade?
print("\nTamanho de amostra para demonstrar um alvo com 0 defeitos observados:")
print("(regra dos 3: n ≈ 3/p para 95% de confiança)")
for alvo_ppm in [10_000, 1_000, 100, 10]:
    p_alvo = alvo_ppm/1e6
    n_req = int(np.ceil(np.log(0.05)/np.log(1-p_alvo)))
    print(f"   Demonstrar < {alvo_ppm:>6,} ppm : n ≥ {n_req:>8,} peças sem qualquer defeito")
```

**Engineering reading.** The last table is a decisive, often-ignored argument: **to demonstrate high quality levels through attribute inspection, sample sizes become impractical.**

Demonstrating under 10 ppm would require hundreds of thousands of parts with not a single defect. That's why, above a certain requirement level, quality assurance **has to** migrate from attribute inspection to:

- variable measurement with capability (far more efficient per part),
- process control instead of product control,
- poka-yoke prevention (PART III),
- and reliability demonstration and accelerated testing (PART XI).

This is one of the strongest statistical justifications for the entire lean and Six Sigma philosophy: **you don't inspect quality into the product** — not for philosophical reasons, but because sampling arithmetic simply doesn't allow it.

### Common mistakes

1. **Testing for normality and removing "outliers" until it passes.** In characteristics that are skewed by nature, the tail values are the process, not errors.
2. **Using Box-Cox and reporting the transformed $C_{pk}$ without flagging it.** The number is no longer comparable to $C_{pk}$ from other processes.
3. **Fitting a distribution without checking goodness of fit.** The choice of distribution mainly affects the tails — which is exactly the zone that determines ppm.
4. **Extrapolating to ppm far beyond the data's range.** Predicting 3 ppm from 200 observations is extrapolating 3 orders of magnitude beyond what was observed. Report the uncertainty.
5. **Reporting "0 defects" as capability.** Always report it with the confidence interval and $n$.
6. **Applying the 1.5σ shift to data that's already long-term.** Doubles the correction.
