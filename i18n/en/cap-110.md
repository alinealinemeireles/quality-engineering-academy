## Chapter 110: Data Governance: Ownership, Definitions and Traceability ✦

### The engineering question

*When two people present different PPM figures for the same month, which one is right?*

Almost always, both — because they're calculating different things under the same name. One includes rework, the other doesn't. One counts by production date, the other by detection date. One excludes lots rejected at receiving, the other doesn't.

Data governance is the set of decisions that prevents this situation. It isn't technology; it's the same **operational-definition** work that the Measure phase of DMAIC requires — applied to the entire organization.

### The four pillars

**1. Ownership**

| Role | Responsibility |
|---|---|
| **Data Owner** | Accountable for the data domain. Approves definitions and access. Typically an area manager, not IT |
| **Data Steward** | Looks after day-to-day quality. Investigates anomalies. Usually the quality engineer |
| **Data Custodian** | Operates the infrastructure. IT |
| **Data Consumer** | Uses the data. Should report anomalies |

**2. Data dictionary and operational definitions**

Every indicator needs: name, clear plain-language definition, exact formula, source, numerator, denominator, **exclusions**, granularity, frequency and owner.

> The **exclusions** field is what resolves most arguments. "Supplier PPM" — does it include parts rejected at receiving? Does it include parts returned without analysis? Does it include accepted rework? Each answer gives a different, equally defensible number.

**3. Version and change control**

A change to an indicator's definition is a **change to the management system** and should follow the change-management process: request, impact analysis, approval, communication, effective date, and **recalculating the history or flagging the series break**.

**4. Access and retention**

Who sees what, how long it's kept, and how it's disposed of. In an automotive context, quality-record retention has long contractual requirements (often tied to product life plus a period); in a personal-data context, GDPR imposes the opposite — minimization and limited retention. The two obligations coexist and sometimes collide: traceability data that identifies operators is simultaneously a quality record and personal data.

### Worked example: the same question, four legitimate answers

```py-r
--- python
import pandas as pd
import numpy as np

rng = np.random.default_rng(77)
n = 5000

d = pd.DataFrame({
    "id": range(n),
    "data_producao": pd.to_datetime("2026-06-01") + pd.to_timedelta(rng.integers(0,30,n), unit="D"),
    "data_detecao":  pd.to_datetime("2026-06-01") + pd.to_timedelta(rng.integers(0,45,n), unit="D"),
    "estado":     rng.choice(["OK","NOK","RETRABALHADO_OK"], n, p=[0.93, 0.04, 0.03]),
    "origem":     rng.choice(["producao","rececao"], n, p=[0.85, 0.15]),
    "amostra":    rng.choice([True, False], n, p=[0.2, 0.8]),
})
d.loc[d.data_detecao < d.data_producao, "data_detecao"] = d["data_producao"]

def ppm(sub, defeito_mask):
    return 1e6*defeito_mask.sum()/len(sub) if len(sub) else np.nan

junho = lambda col: (d[col].dt.month == 6)

definicoes = [
 ("A — só NOK, por data de produção, tudo incluído",
  d[junho("data_producao")], lambda s: s.estado == "NOK"),
 ("B — NOK + retrabalhado, por data de produção",
  d[junho("data_producao")], lambda s: s.estado.isin(["NOK","RETRABALHADO_OK"])),
 ("C — só NOK, por data de DETEÇÃO",
  d[junho("data_detecao")], lambda s: s.estado == "NOK"),
 ("D — só NOK de produção (exclui receção), por data de produção",
  d[junho("data_producao") & (d.origem == "producao")], lambda s: s.estado == "NOK"),
]

print("PPM DE JUNHO — quatro definições, todas defensáveis\n")
linhas = []
for nome, sub, mask in definicoes:
    m = mask(sub)
    linhas.append({"Definição": nome, "n": len(sub), "defeitos": int(m.sum()),
                   "PPM": round(ppm(sub, m))})
res = pd.DataFrame(linhas)
print(res.to_string(index=False))
print(f"\nAmplitude entre a maior e a menor: "
      f"{res.PPM.max() - res.PPM.min():,} ppm "
      f"(fator de {res.PPM.max()/res.PPM.min():.1f}x)")
print("\nSe o objetivo contratual com o cliente for 40.000 ppm, a definição")
print("escolhida determina se a empresa cumpre ou não — sem que nada mude")
print("no processo produtivo.")

# ---------- A ficha de indicador que resolve o problema ----------
ficha = {
    "indicador": "PPM_CLIENTE",
    "definicao": "Peças por milhão entregues ao cliente que foram rejeitadas por não conformidade",
    "formula": "1e6 * (nº de peças NOK) / (nº total de peças entregues)",
    "numerador": "estado == 'NOK' AND origem == 'producao'",
    "denominador": "todas as peças com origem == 'producao'",
    "exclusoes": [
        "peças rejeitadas na receção de material (contam para PPM_FORNECEDOR)",
        "peças retrabalhadas e aprovadas (contam para TAXA_RETRABALHO)",
        "peças de amostragem destrutiva e ensaio",
    ],
    "criterio_temporal": "data de PRODUÇÃO (não de deteção)",
    "granularidade": "mês / linha / referência",
    "fonte": "MES.medicoes JOIN ERP.nao_conformidades",
    "frequencia": "mensal, fechado ao 5º dia útil",
    "data_owner": "Diretor de Qualidade",
    "data_steward": "Engenheiro da Qualidade da área",
    "versao": "2.1",
    "em_vigor_desde": "2026-01-01",
    "alteracao_anterior": "v2.0 incluía retrabalho no numerador; alterado por "
                          "decisão do Comité da Qualidade de 2025-11-18; "
                          "série histórica recalculada até 2024-01",
}
print("\n\nFICHA DE INDICADOR (o instrumento de governança)")
for k, v in ficha.items():
    if isinstance(v, list):
        print(f"   {k}:")
        for item in v: print(f"      - {item}")
    else:
        print(f"   {k}: {v}")

print("\nOs dois campos que mais discussões evitam: 'exclusoes' e")
print("'alteracao_anterior'. O segundo é o que impede comparar séries")
print("calculadas com definições diferentes.")
```

### The connection to ISO 9001 and IATF

Data governance is not a discipline running parallel to the management system — it's an application of it:

| Management-system requirement | Data equivalent |
|---|---|
| Control of documented information | Versioning of definitions and queries |
| Traceability | Data lineage |
| Control of measuring equipment | Validation of the systems that generate data |
| Competence | Training in SQL and data literacy |
| Change management | Process for changing indicator definitions |
| Internal audit | Data-quality audit |
| Objective evidence | Reproducibility of the calculation |

> If an organization tightly controls the calibration of its calipers and controls nothing about the spreadsheet that decides whether a lot is accepted, it has a serious inconsistency in its management system — and it's an inconsistency a competent auditor will find.

### Common mistakes

1. **Governance with no named owner.** Committees with no individual accountable don't decide anything.
2. **A data dictionary nobody consults.** It should be linked to the dashboard: every indicator one click away from its definition.
3. **Changing definitions without flagging the series break.** It produces fictitious "improvements" and destroys the credibility of the indicators.
4. **Confusing governance with access restriction.** Locking down data is the easy part and often counterproductive. Governance is mainly about definitions and accountability.
5. **Excluding quality from data governance.** If it's run solely by IT, it produces a catalog that's technically correct and operationally useless.
