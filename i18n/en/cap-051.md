## Chapter 51: Multiple Regression: Diagnostics, Multicollinearity, and Model Selection
### The engineering question

*The model fits well — but fits well *to what*, and what does that authorize me to do to the process?*

A high $R^2$ authorizes nothing. A regression model can have $R^2 = 0{.}95$ and simultaneously be: useless for prediction outside the observed range, dangerous for causal decisions, and statistically invalid. The engineering work begins **after** the model fits.

### The model and its assumptions

$$Y = \beta_0 + \beta_1 X_1 + \dots + \beta_p X_p + \varepsilon, \qquad \varepsilon \sim N(0, \sigma^2) \;\text{i.i.d.}$$

The assumptions, and how each one fails in industrial practice:

| Assumption | How to check it | Typical industry failure |
|---|---|---|
| **Linearity** in the parameters | Residuals vs. fitted values | The real relationship is curved (temperature, concentration) |
| **Independence** of residuals | Durbin-Watson; residual ACF | Data in the temporal order of a continuous process |
| **Homoscedasticity** | Residuals vs. fitted; Breusch-Pagan | Variance grows with the level (common in positive measurements) |
| **Normality** of residuals | QQ-plot; Shapiro-Wilk | Contamination by special causes |
| **No severe multicollinearity** | VIF | Process predictors are almost always correlated |
| **Controlled influential observations** | Cook's distance, leverage | A point from an anomalous lot dominates the fit |

> **The order to check things in:** linearity and independence first (they invalidate the model), homoscedasticity and normality next (they affect standard errors and tests), influence last (it affects the estimates).

### Multicollinearity: the silent problem

$$VIF_j = \frac{1}{1 - R_j^2}$$

where $R_j^2$ is the $R^2$ from regressing $X_j$ on the remaining predictors.

| VIF | Interpretation |
|---|---|
| 1 | Predictor orthogonal to the rest (the situation in a well-designed DOE) |
| < 5 | Acceptable |
| 5 – 10 | Caution; unstable coefficients |
| > 10 | Severe multicollinearity |

**What multicollinearity does and doesn't do:**

- **Does**: inflates the coefficients' standard errors, makes signs unstable (a coefficient can flip sign when a variable is added), and destroys the individual interpretation of each $\beta$.
- **Doesn't**: hurt predictive ability within the observed domain. A model with high VIF can predict well and still be unusable for deciding what to adjust in the process.

**The implication for quality engineering is direct.** Observational process data almost always has correlated predictors, because the process is run within a narrow window and the variables move together. Asking "which of these variables should I adjust?" of collinear observational data is a question the data **cannot** answer.

> **The fix for multicollinearity isn't statistical, it's experimental.** A DOE generates orthogonal predictors by construction (VIF = 1) and gives interpretability back. This is the deep reason PART VIII exists.

### Worked example: complete diagnostics

```py-r
--- python
import numpy as np
import pandas as pd
import statsmodels.api as sm
import statsmodels.formula.api as smf
from statsmodels.stats.outliers_influence import variance_inflation_factor
from statsmodels.stats.diagnostic import het_breuschpagan, acorr_ljungbox
from statsmodels.stats.stattools import durbin_watson
from scipy import stats
import matplotlib.pyplot as plt

rng = np.random.default_rng(2026)
n = 120

# Processo de extrusão: preditores correlacionados, como em dados observacionais reais
temp = rng.normal(210, 6, n)
pressao = 0.55*temp + rng.normal(0, 3, n)          # fortemente ligada à temperatura
veloc = rng.normal(45, 5, n)
humidade = rng.normal(38, 7, n)                     # sem efeito real

# Resposta com efeito curvo na temperatura e sem efeito da humidade
espessura = (2.10 + 0.030*(temp-210) - 0.0025*(temp-210)**2
             + 0.018*(veloc-45) + rng.normal(0, 0.045, n))

d = pd.DataFrame({"espessura": espessura, "temp": temp, "pressao": pressao,
                  "veloc": veloc, "humidade": humidade})

# ---------- Modelo 1: tudo linear ----------
m1 = smf.ols("espessura ~ temp + pressao + veloc + humidade", data=d).fit()
print("MODELO 1 — todos os preditores, lineares")
print(f"R² = {m1.rsquared:.4f} | R² ajustado = {m1.rsquared_adj:.4f} | AIC = {m1.aic:.1f}")
print(m1.summary2().tables[1].round(4).to_string())

# ---------- VIF ----------
X = sm.add_constant(d[["temp", "pressao", "veloc", "humidade"]])
vif = pd.DataFrame({
    "Preditor": X.columns[1:],
    "VIF": [variance_inflation_factor(X.values, i) for i in range(1, X.shape[1])]
}).round(2)
vif["Leitura"] = pd.cut(vif["VIF"], [0, 5, 10, np.inf],
                        labels=["aceitável", "atenção", "SEVERA"])
print("\nFATOR DE INFLAÇÃO DA VARIÂNCIA")
print(vif.to_string(index=False))
print(f"\nCorrelação temp–pressao: {d[['temp','pressao']].corr().iloc[0,1]:.3f}")
print("=> os coeficientes de temp e pressao NÃO podem ser interpretados isoladamente.")

# ---------- Diagnósticos dos resíduos ----------
print("\nDIAGNÓSTICO DOS PRESSUPOSTOS (modelo 1)")
res = m1.resid
dw = durbin_watson(res)
bp = het_breuschpagan(res, m1.model.exog)
sw = stats.shapiro(res)
# teste RESET de Ramsey para falta de ajuste (não-linearidade omitida)
from statsmodels.stats.diagnostic import linear_reset
reset = linear_reset(m1, power=2, test_type="fitted", use_f=True)
print(f"  Independência (Durbin-Watson) : {dw:.3f}  "
      f"({'ok' if 1.5 < dw < 2.5 else 'AUTOCORRELAÇÃO'})")
print(f"  Homocedasticidade (Breusch-Pagan): p = {bp[1]:.4f}  "
      f"({'ok' if bp[1] > 0.05 else 'HETEROCEDÁSTICO'})")
print(f"  Normalidade (Shapiro-Wilk)     : p = {sw.pvalue:.4f}  "
      f"({'ok' if sw.pvalue > 0.05 else 'NÃO NORMAL'})")
print(f"  Especificação (RESET de Ramsey): p = {reset.pvalue:.4g}  "
      f"({'ok' if reset.pvalue > 0.05 else 'FALTA TERMO NÃO-LINEAR'})")

# ---------- Modelo 2: corrigir a especificação ----------
d["temp_c"] = d["temp"] - d["temp"].mean()          # centrar antes de elevar ao quadrado
d["veloc_c"] = d["veloc"] - d["veloc"].mean()
m2 = smf.ols("espessura ~ temp_c + I(temp_c**2) + veloc_c", data=d).fit()
print("\nMODELO 2 — termo quadrático, preditores centrados, sem redundâncias")
print(f"R² = {m2.rsquared:.4f} | R² ajustado = {m2.rsquared_adj:.4f} | AIC = {m2.aic:.1f}")
print(m2.summary2().tables[1].round(5).to_string())
reset2 = linear_reset(m2, power=2, test_type="fitted", use_f=True)
print(f"\n  RESET de Ramsey no modelo 2: p = {reset2.pvalue:.3f} "
      f"({'especificação adequada' if reset2.pvalue > 0.05 else 'ainda mal especificado'})")

Xc = sm.add_constant(d[["temp_c", "veloc_c"]])
print(f"  VIF do modelo 2: " + ", ".join(
    f"{c}={variance_inflation_factor(Xc.values, i):.2f}"
    for i, c in enumerate(Xc.columns) if i > 0))

print(f"\nComparação:  AIC modelo 1 = {m1.aic:.1f}  |  AIC modelo 2 = {m2.aic:.1f}"
      f"  -> {'modelo 2 melhor' if m2.aic < m1.aic else 'modelo 1 melhor'}")

# ---------- Observações influentes ----------
inf = m2.get_influence()
cook = inf.cooks_distance[0]
lev = inf.hat_matrix_diag
lim_cook = 4/len(d)
crit = np.where(cook > lim_cook)[0]
print(f"\nOBSERVAÇÕES INFLUENTES (Cook > 4/n = {lim_cook:.4f}): "
      f"{len(crit)} de {len(d)}  -> índices {list(crit[:8])}")

fig, axes = plt.subplots(2, 3, figsize=(14, 7))
axes[0,0].scatter(m1.fittedvalues, m1.resid, s=14, alpha=0.7)
axes[0,0].axhline(0, color="r", ls="--"); axes[0,0].set_title("M1: resíduos vs ajustados\n(padrão curvo = má especificação)")
stats.probplot(m1.resid, plot=axes[0,1]); axes[0,1].set_title("M1: QQ-plot")
axes[0,2].scatter(d["temp"], d["espessura"], s=14, alpha=0.7)
axes[0,2].set_xlabel("temperatura"); axes[0,2].set_ylabel("espessura")
axes[0,2].set_title("Relação real: curva")
axes[1,0].scatter(m2.fittedvalues, m2.resid, s=14, alpha=0.7, color="green")
axes[1,0].axhline(0, color="r", ls="--"); axes[1,0].set_title("M2: resíduos vs ajustados")
stats.probplot(m2.resid, plot=axes[1,1]); axes[1,1].set_title("M2: QQ-plot")
axes[1,2].stem(cook, markerfmt=","); axes[1,2].axhline(lim_cook, color="r", ls="--")
axes[1,2].set_title("M2: distância de Cook")
plt.tight_layout(); plt.show()
```

```py-r
%%R
set.seed(2026)
n <- 120
temp <- rnorm(n, 210, 6)
pressao <- 0.55*temp + rnorm(n, 0, 3)
veloc <- rnorm(n, 45, 5)
humidade <- rnorm(n, 38, 7)
espessura <- 2.10 + 0.030*(temp-210) - 0.0025*(temp-210)^2 + 0.018*(veloc-45) + rnorm(n, 0, 0.045)
d <- data.frame(espessura, temp, pressao, veloc, humidade)

m1 <- lm(espessura ~ temp + pressao + veloc + humidade, data = d)
cat("MODELO 1\n"); print(summary(m1)$coefficients)
cat(sprintf("R2 = %.4f | AIC = %.1f\n", summary(m1)$r.squared, AIC(m1)))

# VIF sem dependencias externas
vif_manual <- function(modelo) {
  X <- model.matrix(modelo)[, -1, drop = FALSE]
  sapply(seq_len(ncol(X)), function(j) 1/(1 - summary(lm(X[,j] ~ X[,-j]))$r.squared))
}
v <- vif_manual(m1); names(v) <- c("temp","pressao","veloc","humidade")
cat("\nVIF:\n"); print(round(v, 2))

d$temp_c <- d$temp - mean(d$temp); d$veloc_c <- d$veloc - mean(d$veloc)
m2 <- lm(espessura ~ temp_c + I(temp_c^2) + veloc_c, data = d)
cat("\nMODELO 2\n"); print(summary(m2)$coefficients)
cat(sprintf("R2 = %.4f | AIC = %.1f\n", summary(m2)$r.squared, AIC(m2)))
cat(sprintf("\nShapiro dos residuos M2: p = %.3f\n", shapiro.test(residuals(m2))$p.value))
```

**Engineering reading.** Three lessons come out of the example.

**First: Ramsey's RESET caught what $R^2$ hid.** Model 1 has a respectable $R^2$, but it's misspecified — the quadratic term is missing. Using it to optimize temperature would lead in the wrong direction, because a linear model on a relationship with a maximum always points to the edge of the domain.

**Second: the pressure coefficient isn't interpretable.** With high VIF, pressure and temperature move together, and the model can't separate their effects. Concluding "pressure isn't significant, so it doesn't affect thickness" is an invalid inference.

**Third: center before squaring.** Without centering, `temp` and `temp²` have a correlation above 0.99 and the multicollinearity becomes artificial — created by the algebra, not the physics.

### Model selection: what to do and what not to do

**Don't: automatic *stepwise* selection guided by p-values.** It produces overfitting, biased p-values (the final tests ignore that they were chosen from among many), and models that don't replicate. It's one of the most criticized practices in modern statistical literature and remains the default option in a lot of software.

**Do:**

1. **Start from the physics.** Which variables does engineering say matter? A model with 4 grounded predictors beats a model with 15 selected by an algorithm.
2. **Compare by AIC/BIC** a small set of candidate models defined *a priori*.
3. **Validate out of sample.** Cross-validation or, better, a data set from a different period.
4. **Report prediction intervals, not just confidence intervals.** The confidence interval is for the mean; the **prediction interval** is for a future observation, and it's what matters to whoever will use the model to decide about the next part. It's always much wider — and that width is what the user needs to see.

```py-r
--- python
import numpy as np, pandas as pd
# Intervalo de confiança vs intervalo de previsão — a distinção que mais confunde
novo = pd.DataFrame({"temp_c": [0.0, 5.0, -5.0], "veloc_c": [0.0, 0.0, 0.0]})
pred = m2.get_prediction(novo)
sf = pred.summary_frame(alpha=0.05).round(4)
sf.insert(0, "temp (°C)", novo["temp_c"] + d["temp"].mean())
print(sf[["temp (°C)", "mean", "mean_ci_lower", "mean_ci_upper",
          "obs_ci_lower", "obs_ci_upper"]].to_string(index=False))
larg_ic = (sf["mean_ci_upper"]-sf["mean_ci_lower"]).mean()
larg_ip = (sf["obs_ci_upper"]-sf["obs_ci_lower"]).mean()
print(f"\nLargura média do IC da média   : {larg_ic:.4f} mm")
print(f"Largura média do IC de previsão: {larg_ip:.4f} mm  ({larg_ip/larg_ic:.1f}x mais largo)")
print("\nSe a tolerância for ±0,10 mm, é o intervalo de PREVISÃO que tem de caber nela,")
print("não o intervalo de confiança da média.")
```

Power BI's role here is operational: the coefficients are **calculated externally** (Python/R) and imported into a `ModeloRegressao` table; the `Alerta Fora do Envelope` measure prevents, right on the dashboard, someone reading a prediction outside the observed data envelope — mistake #3 listed under "Common mistakes" below.

### Common mistakes

1. **Reporting $R^2$ as a measure of model quality.** $R^2$ always grows when a predictor is added, even a random one. Use adjusted $R^2$ to compare, and diagnostics to validate.
2. **Interpreting coefficients with high VIF.** See above.
3. **Extrapolating.** The model is only valid within the envelope of the observed data. Predicting at 260 °C with data from 195–225 °C is fiction.
4. **Confusing association with causation in observational data.** Regression describes conditional association. Only DOE provides a causal basis.
5. **Not centering before polynomial terms or interactions.**
6. **Ignoring temporal order.** If the data comes from a process in sequence, test the residuals for autocorrelation. If it exists, the standard errors are wrong and every p-value is invalid.
