## Chapter 111: Machine Learning Applied to Quality: Where It Helps and Where It Misleads
### The engineering question

*Do I need to predict, or do I need to understand?*

This question separates the problems where machine learning is the right tool from those where it's an expensive distraction.

| Goal | Right tool |
|---|---|
| **Predict** an outcome as accurately as possible | ML (random forests, gradient boosting, neural nets) |
| **Understand** which factor causes what, and by how much to adjust it | **DOE** and statistical models |
| **Detect** that something has changed | SPC, multivariate T², anomaly detection |
| **Decide** whether the difference is real | Hypothesis tests, confidence intervals |

> **ML describes associations in the data it has seen.** It does not establish causality, and a model with 96% accuracy can be useless for deciding what to change in the process — because the most predictive variable may be a consequence of the defect, not a cause.

### Where ML adds real value in quality

| Application | Why it works |
|---|---|
| **Automated visual inspection** | Computer vision consistently outperforms repetitive human inspection, and doesn't get fatigued |
| **Predictive maintenance** | Many sensors, complex patterns, prediction is the actual goal (not explanation) |
| **Multivariate anomaly detection** | A natural extension of T² to non-linear relationships |
| **Classifying free-text complaints** | NLP replaces inconsistent manual coding |
| **Inspection prioritization** | Concentrating resources where the risk is highest |
| **Yield forecasting** | Anticipating lot problems before the end of the process |

### The five mistakes that invalidate ML projects in quality

**1. Data leakage.** A training-set variable contains information that only exists *after* the outcome is known. Symptom: surprisingly high accuracy. It's the most frequent mistake and the most embarrassing one, because it only shows up in production.

**2. Wrong validation with time-ordered data.** Random cross-validation on data with temporal structure trains on the future and tests on the past. Use temporal validation (forward chaining).

**3. Poorly handled class imbalance.** With 2% defects, a model that always answers "OK" has 98% accuracy. **Accuracy is the wrong metric.** Use precision, recall, F1, and above all the **precision-recall curve**.

**4. Model drift.** The process changes; the model doesn't. Without monitoring, it degrades silently. A model in production needs a **control chart** on its own performance — SPC applied to the model.

**5. Missing explainability when it's mandatory.** If the model decides whether to accept or reject product, the standard and the customer will demand justification for the decision. A model that is technically better but opaque can be contractually unusable.

### Worked example: predicting scrap, with every trap included

```py-r
--- python
import numpy as np
import pandas as pd

rng = np.random.default_rng(123)
n = 3000

# --- Dados de processo ---
temp = rng.normal(215, 7, n)
pressao = rng.normal(4.2, 0.3, n)
veloc = rng.normal(48, 6, n)
desgaste = rng.uniform(0, 100, n)          # % de vida da ferramenta
lote_mp = rng.choice(["L1","L2","L3"], n, p=[.5,.3,.2])

risco = (-5.4 + 0.055*(temp-215) + 1.8*(pressao-4.2) + 0.038*desgaste
         + 0.9*(lote_mp == "L3") + 0.02*(veloc-48))
p_def = 1/(1+np.exp(-risco))
defeito = rng.binomial(1, p_def)

# --- A ARMADILHA: uma variável medida DEPOIS do resultado ---
tempo_ciclo_real = 30 + 0.1*veloc + 2.0*defeito + rng.normal(0, 1.4, n)
#                                    ^^^^^^^^^^ peças defeituosas param a linha

d = pd.DataFrame({"temp": temp, "pressao": pressao, "veloc": veloc,
                  "desgaste": desgaste, "lote_mp": lote_mp,
                  "tempo_ciclo": tempo_ciclo_real, "defeito": defeito})
d["ordem"] = np.arange(n)      # ordem temporal de produção

print(f"n = {n} | taxa de defeito = {d.defeito.mean():.2%} "
      f"({d.defeito.sum()} defeitos)\n")

# ---------- Modelo simples e transparente: regressão logística ----------
import statsmodels.formula.api as smf
import statsmodels.api as sm

def avaliar(y_true, p_pred, limiar=0.5, rotulo=""):
    y_hat = (p_pred >= limiar).astype(int)
    tp = int(((y_hat==1)&(y_true==1)).sum()); fp = int(((y_hat==1)&(y_true==0)).sum())
    fn = int(((y_hat==0)&(y_true==1)).sum()); tn = int(((y_hat==0)&(y_true==0)).sum())
    prec = tp/(tp+fp) if tp+fp else 0.0
    rec  = tp/(tp+fn) if tp+fn else 0.0
    f1 = 2*prec*rec/(prec+rec) if prec+rec else 0.0
    exat = (tp+tn)/len(y_true)
    # AUC
    o = np.argsort(-p_pred); yy = np.asarray(y_true)[o]
    tpr = np.concatenate([[0], np.cumsum(yy)/max(yy.sum(),1)])
    fpr = np.concatenate([[0], np.cumsum(1-yy)/max((1-yy).sum(),1)])
    auc = np.trapezoid(tpr, fpr) if hasattr(np,"trapezoid") else np.trapz(tpr,fpr)
    return {"Modelo": rotulo, "Exatidão": round(exat,4), "Precisão": round(prec,3),
            "Revocação": round(rec,3), "F1": round(f1,3), "AUC": round(auc,3),
            "TP": tp, "FP": fp, "FN": fn}

# Divisão TEMPORAL (não aleatória)
corte = int(0.7*n)
tr, te = d.iloc[:corte], d.iloc[corte:]

m_bom = smf.glm("defeito ~ temp + pressao + veloc + desgaste + C(lote_mp)",
                data=tr, family=sm.families.Binomial()).fit()
m_vazado = smf.glm("defeito ~ temp + pressao + veloc + desgaste + C(lote_mp)"
                   " + tempo_ciclo", data=tr, family=sm.families.Binomial()).fit()

res = pd.DataFrame([
    avaliar(te.defeito.values, m_bom.predict(te).values, 0.15,
            "Só variáveis de PROCESSO (correto)"),
    avaliar(te.defeito.values, m_vazado.predict(te).values, 0.15,
            "Com tempo_ciclo (FUGA DE INFORMAÇÃO)"),
])
print("1) O EFEITO DA FUGA DE INFORMAÇÃO")
print(res.to_string(index=False))
print(f"\n   O segundo modelo parece muito melhor. Mas 'tempo_ciclo' só é")
print(f"   conhecido DEPOIS de a peça ser produzida e a linha parar por causa do")
print(f"   defeito. Em produção, no momento em que a previsão seria útil, essa")
print(f"   variável não existe. O modelo é inútil — e ninguém repara até ao piloto.")
print(f"\n   Coeficiente de tempo_ciclo: {m_vazado.params['tempo_ciclo']:+.3f} "
      f"(p = {m_vazado.pvalues['tempo_ciclo']:.2e})")
print(f"   Um preditor 'demasiado bom' deve sempre levantar suspeita de fuga.")

# ---------- 2. A exatidão é a métrica errada ----------
print("\n\n2) POR QUE A EXATIDÃO ENGANA COM CLASSES DESEQUILIBRADAS")
sempre_ok = np.zeros(len(te))
print(f"   Modelo trivial 'nunca há defeito': exatidão = "
      f"{(te.defeito.values == 0).mean():.4f}")
print(f"   ... e revocação = 0,000. Não deteta um único defeito.")
print(f"   É por isso que se reporta precisão, revocação e F1 — nunca só exatidão.")

# ---------- 3. Escolher o limiar pelos CUSTOS, não por 0,5 ----------
print("\n\n3) O LIMIAR DE DECISÃO É UMA DECISÃO ECONÓMICA")
custo_fn = 320.0    # defeito que chega ao cliente
custo_fp = 12.0     # peça boa inspecionada/rejeitada sem necessidade
p_te = m_bom.predict(te).values
linhas = []
for lim in [0.01, 0.02, 0.04, 0.06, 0.10, 0.15, 0.25, 0.50]:
    r = avaliar(te.defeito.values, p_te, lim)
    custo = r["FN"]*custo_fn + r["FP"]*custo_fp
    linhas.append({"Limiar": lim, "Precisão": r["Precisão"], "Revocação": r["Revocação"],
                   "FN (escapam)": r["FN"], "FP (falsos alarmes)": r["FP"],
                   "Custo total (€)": round(custo)})
tab = pd.DataFrame(linhas)
tab["<-- ótimo"] = np.where(tab["Custo total (€)"] == tab["Custo total (€)"].min(), "  <<<", "")
print(tab.to_string(index=False))
otimo = tab.loc[tab["Custo total (€)"].idxmin()]
print(f"\n   O limiar que minimiza custo é {otimo['Limiar']}, não 0,5.")
print(f"   Com custo_FN/custo_FP = {custo_fn/custo_fp:.0f}, compensa aceitar muitos")
print(f"   falsos alarmes para evitar um escape.")

# ---------- 4. Deriva do modelo ----------
print("\n\n4) DERIVA DO MODELO — SPC aplicado ao próprio modelo")
te2 = te.copy()
te2["bloco"] = pd.qcut(te2["ordem"], 6, labels=False)
# simular deriva do processo na segunda metade do período de teste
te2.loc[te2["bloco"] >= 3, "desgaste"] = np.clip(
    te2.loc[te2["bloco"] >= 3, "desgaste"] + 25, 0, 100)
desemp = []
for b, g in te2.groupby("bloco"):
    p = m_bom.predict(g).values
    r = avaliar(g.defeito.values, p, float(otimo["Limiar"]))
    desemp.append({"Bloco": b, "n": len(g), "Taxa real": round(g.defeito.mean(),4),
                   "Taxa prevista média": round(p.mean(),4),
                   "Revocação": r["Revocação"], "Precisão": r["Precisão"]})
dd = pd.DataFrame(desemp)
dd["Calibração (prev/real)"] = (dd["Taxa prevista média"]/
                                dd["Taxa real"].replace(0, np.nan)).round(2)
print(dd.to_string(index=False))
print("\n   Quando a coluna de calibração se afasta de 1, o modelo deixou de")
print("   descrever o processo. Este indicador deve estar numa CARTA DE CONTROLO,")
print("   com plano de reação: reavaliar, retreinar ou desativar o modelo.")
```

### The validation quality demands, and that data science usually forgets

A model that makes decisions about product is, in practice, a **measurement system**. And a measurement system is subject to MSA.

| MSA concept | Model equivalent |
|---|---|
| Repeatability | Does the model give the same result for the same input? (version, seed, rounding) |
| Reproducibility | Does it give the same result on different machines/environments? |
| Bias | Does it systematically over- or under-estimate the defect rate? |
| Stability | Does performance hold up over time? (drift) |
| Linearity | Is performance uniform across the whole operating range, or worse at the extremes? |
| Attribute agreement analysis | **Kappa between the model and the reference human inspector** |

> This last row is the most important and the most often forgotten: before replacing a human inspection with a model, run an **attribute agreement study** between the model, the current inspectors, and a reference standard. It's common to discover that the human reference standard itself had a modest Kappa — which changes how the model's performance should be interpreted.

### Common mistakes

1. **Data leakage.** Rule of thumb: for every variable, ask *"would this information exist at the moment I need the prediction?"*
2. **Random cross-validation on time-ordered data.**
3. **Reporting accuracy on imbalanced problems.**
4. **Defaulting to a 0.5 threshold.** It's an economic decision.
5. **A model in production with no monitoring.** It needs a control chart and a reaction plan, like any process.
6. **Unnecessary complexity.** A logistic regression that can be explained to the customer and to an auditor is worth more than an opaque model that's 2% better. Always start with the simple model, and only abandon it if the gain justifies the cost in explainability.
7. **Confusing variable importance with causality.** Importance measures predictive usefulness. To know what to change in the process, run a DOE.
