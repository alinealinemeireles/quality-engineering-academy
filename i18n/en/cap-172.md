## Chapter 172: Interpretability with SHAP

<h3 id="the-engineering-question">The engineering question</h3>
<p><em>The Random Forest from <a href="#/aula/cap-171">Chapter 171</a> correctly flagged 94% of risk lots. The quality manager asks: “why was <strong>this</strong> specific lot flagged?” — not on average, this lot.</em></p>
<p><code>feature_importances_</code> answers in aggregate: on average, across the whole training set, tool wear matters more than temperature. That doesn’t help explain an individual decision — and in a quality audit, a customer complaint, or a regulatory requirement, it’s exactly the individual explanation that gets asked for. That’s the gap Shapley values (SHAP) fill.</p>
<h3 id="shapley-values-intuition-without-the-full-game-theory">Shapley values: intuition without the full game theory</h3>
<p>The idea, borrowed from cooperative game theory, is to fairly distribute the difference between the model’s prediction for a specific observation and the model’s average prediction (the “baseline”) among the variables that contributed to that difference:</p>
<p><div class="math-block" data-math="f(x) = f_{\text{base}} + \sum_{j=1}^{p} \phi_j"></div></p>
<p>where <span class="math-inline" data-math="\phi_j"></span> is variable <span class="math-inline" data-math="j"></span>’s Shapley value for that specific observation — the average marginal contribution of that variable, considered across every possible order in which the variables could be “revealed” to the model. A positive <span class="math-inline" data-math="\phi_j"></span> pushed the prediction up relative to the baseline; a negative one pushed it down. The sum of all <span class="math-inline" data-math="\phi_j"></span> plus the baseline reconstructs exactly the model’s prediction for that point — that property is what makes SHAP consistent, and different from other importance measures that carry no such mathematical guarantee.</p>
<h3 id="treeexplainer-efficient-shap-for-tree-models">TreeExplainer: efficient SHAP for tree models</h3>
<p>Computing exact Shapley values, considering every possible variable ordering, is computationally infeasible for generic models with many variables. <code>TreeExplainer</code> exploits the internal structure of decision trees to compute exact values in polynomial time instead of exponential — which is why it’s the standard choice for Random Forest and XGBoost, and it requires an <strong>already-trained</strong> tree model as input (the model from <a href="#/aula/cap-171">Chapter 171</a>, not a linear regression — for linear or generic models there’s <code>LinearExplainer</code>/<code>KernelExplainer</code>, slower and out of scope here).</p>
<h3 id="summary-plot-global-importance-and-per-observation-effect">Summary plot: global importance and per-observation effect</h3>
<p>The <em>summary</em> plot (also called a <em>beeswarm</em> plot) stacks, for each variable, one point per observation in the dataset: the horizontal position is that observation’s Shapley value (how much that variable pushed the prediction), and the color shows whether <strong>the variable’s value</strong> was high or low for that observation. Variables are ordered top to bottom by mean absolute importance — recovering, in richer form, the same aggregate information as <code>feature_importances_</code>, but now also showing the direction of the effect (does high wear push the prediction up or down?) and the spread across observations (is the effect consistent, or does it depend on other variables?).</p>
<h3 id="worked-example-explaining-one-specific-lot">Worked example: explaining one specific lot</h3>
<div class="codetabs"><div class="ct-bar" role="tablist"><button type="button" class="ct-tab on" role="tab" aria-selected="true" id="ct18450e6f-t0">Python</button></div><div class="ct-pane" role="tabpanel" aria-labelledby="ct18450e6f-t0"><div class="codeblock" data-lang="python"><div class="codebar"><span class="lang">Python</span><button class="btn-copy" type="button">Copiar</button></div><pre><code class="language-python">import numpy as np
import pandas as pd
from sklearn.ensemble import RandomForestClassifier
import shap

rng = np.random.default_rng(2026)
n = 1500

temp = rng.normal(215, 7, n)
pressao = rng.normal(4.2, 0.3, n)
desgaste = rng.uniform(0, 100, n)

risco = (-4.0 + 0.05 * (temp - 215) + 1.4 * (pressao - 4.2)
         + 0.045 * desgaste + 0.002 * np.maximum(temp - 218, 0) * desgaste)
y = rng.binomial(1, 1 / (1 + np.exp(-risco)))

X = pd.DataFrame({"temp": temp, "pressao": pressao, "desgaste": desgaste})

modelo = RandomForestClassifier(n_estimators=300, max_depth=5, random_state=0).fit(X, y)

explainer = shap.TreeExplainer(modelo)
shap_values = explainer.shap_values(X)          # per-observation, per-variable contributions
# Select the positive class (index 1) for binary classification.
# Recent SHAP versions return an ndarray (samples, features, classes);
# older versions return a list with one array per class -- cover both cases.
if isinstance(shap_values, list):
    sv_classe1 = shap_values[1]
elif shap_values.ndim == 3:
    sv_classe1 = shap_values[:, :, 1]
else:
    sv_classe1 = shap_values

print("Mean |SHAP| importance per variable (the summary plot, in numbers):")
importancia = pd.Series(np.abs(sv_classe1).mean(axis=0), index=X.columns).sort_values(ascending=False)
print(importancia.round(4).to_string())

# --- Explaining ONE specific lot, as the quality manager asked ---
idx_lote_critico = int(np.argmax(modelo.predict_proba(X)[:, 1]))
linha = X.iloc[idx_lote_critico]
contrib = pd.Series(sv_classe1[idx_lote_critico], index=X.columns).sort_values(key=abs, ascending=False)

print(f"\nLot #{idx_lote_critico} -- predicted risk probability = "
      f"{modelo.predict_proba(X)[[idx_lote_critico]][0, 1]:.3f}")
print("Input values:")
print(linha.to_string())
print("\nEach variable's contribution to PUSHING this lot away from the average (SHAP):")
print(contrib.round(4).to_string())

base = explainer.expected_value
base_classe1 = base[1] if hasattr(base, "__len__") else base
print(f"\nBaseline (model's average prediction): {base_classe1:.3f}")
print(f"Baseline + sum of contributions = "
      f"{base_classe1 + contrib.sum():.3f}  "
      f"(should match the predicted probability above, on the model's scale)")

That exact reconstruction — impossible to guarantee with <code>feature_importances_</code> alone — is what makes it possible to answer “why <strong>this</strong> lot” instead of only “what matters on average.”</p>
<h3 id="shap-is-not-causality">SHAP is not causality</h3>
<p>The same warning from <a href="#/aula/cap-111">Chapter 111</a> and <a href="#/aula/cap-171">Chapter 171</a> applies here, even more strongly — because a SHAP plot <em>looks</em> more rigorous and tends to convince more easily than it deserves to. SHAP explains <strong>what the model learned</strong>, not <strong>what actually causes the defect in the real process</strong>. If two variables are strongly correlated in the process (for example, tool wear and number of cycles produced), SHAP may attribute high contribution to either one, or split it between the two, without that telling you which of the two is the root cause. For that question, the right tool is still DOE (<a href="#/aula/cap-073">Chapter 73</a>) or a formal causal analysis (<a href="#/aula/cap-137">Chapter 137</a>) — SHAP is a tool for auditing and communicating the model, not for discovering causes.</p>

<h3 id="common-mistakes">Common mistakes</h3>
<ol>
<li><strong>Interpreting a Shapley value as the process’s causal effect.</strong> It’s the model’s contribution to that prediction, not the real effect of changing the variable on the shop floor.</li>
<li><strong>Using the generic <code>KernelExplainer</code> when the model is a tree.</strong> It’s much slower than <code>TreeExplainer</code> with no precision gain for that model type.</li>
<li><strong>Running SHAP before properly validating the model.</strong> Explaining a poorly validated model (see Chapters <a href="#/aula/cap-170">170</a> and <a href="#/aula/cap-171">171</a>) only produces a convincing explanation of a model that doesn’t generalize.</li>
<li><strong>Ignoring correlated variables when reading the summary plot.</strong> Contribution can split between redundant variables in a way that understates their combined importance.</li>
<li><strong>Presenting SHAP as proof of regulatory compliance without context.</strong> SHAP explains the model’s decision; it doesn’t replace statistical validation of the measurement system (MSA) or an assessment of the model’s own risk (<a href="#/aula/cap-138">Chapter 138</a>).</li>
</ol>
