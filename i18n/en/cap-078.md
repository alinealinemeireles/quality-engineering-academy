## Chapter 78: Mixture Experiments and Split-Plot Designs ✦

### Two Situations That Break the Factorial

This chapter covers two cases where the factorial design simply **doesn't apply** — not because it's inefficient, but because it's mathematically invalid.

### Part 1 — Mixture Experiments

**The constraint that changes everything.** In a formulation (paint, concrete, metal alloy, cosmetic, food, drug), the component proportions add up to 100%:

$$\sum_{i=1}^{q} x_i = 1, \qquad x_i \geq 0$$

Consequence: **the factors aren't independent.** You can't "increase component A while holding the rest constant" — increasing A forces something else to decrease. The factorial design matrix becomes singular, and the model with a constant term isn't estimable.

The experimental space stops being a cube and becomes a **simplex**: a triangle with 3 components, a tetrahedron with 4.

**Scheffé's canonical model** (degree 2), with no constant term:

$$y = \sum_{i} \beta_i x_i + \sum_{i<j} \beta_{ij} x_i x_j$$

**Interpretation, which differs from normal regression:**

- $\beta_i$ is the expected response of **pure component** $i$ (with $x_i = 1$).
- $\beta_{ij} > 0$ indicates **synergy** — the blend outperforms the weighted average of the pure components.
- $\beta_{ij} < 0$ indicates **antagonism**.

**Designs:** the *simplex-lattice* $\{q, m\}$ to cover the full simplex; the *simplex-centroid* to include every equal-proportion blend; **D-optimal** when constraints exist (the real-world case, because there are almost always minimums and maximums per component, and the region stops being a regular simplex).

```py-r
--- python
import numpy as np
import pandas as pd
import statsmodels.formula.api as smf
from scipy import optimize
import matplotlib.pyplot as plt

rng = np.random.default_rng(3030)

# --- Simplex-centroid com 3 componentes + pontos axiais ---
pts = [
    (1,0,0), (0,1,0), (0,0,1),                            # puros
    (.5,.5,0), (.5,0,.5), (0,.5,.5),                      # binários
    (1/3,1/3,1/3),                                        # centro
    (2/3,1/6,1/6), (1/6,2/3,1/6), (1/6,1/6,2/3),          # axiais
]
mix = pd.DataFrame(pts, columns=["A","B","C"])
mix = pd.concat([mix, mix.iloc[[6]]], ignore_index=True)   # réplica do centro

# Verdade: A e B em sinergia; C isolado é fraco
def verdade_mix(A, B, C):
    return 42*A + 38*B + 25*C + 46*A*B - 8*A*C + 12*B*C
mix["resistencia"] = verdade_mix(mix.A, mix.B, mix.C) + rng.normal(0, 0.8, len(mix))

print("DESENHO SIMPLEX-CENTROID (3 componentes)")
print(mix.round(4).to_string(index=False))
print(f"\nVerificação da restrição: soma = "
      f"{mix[['A','B','C']].sum(axis=1).unique().round(6)}\n")

# Modelo de Scheffé: SEM termo constante (o -1 remove o intercepto)
ms = smf.ols("resistencia ~ A + B + C + A:B + A:C + B:C - 1", data=mix).fit()
print("MODELO CANÓNICO DE SCHEFFÉ (grau 2)")
print(ms.summary2().tables[1].round(3).to_string())
print(f"\nR² = {ms.rsquared:.4f}")

print("\nINTERPRETAÇÃO")
for c in "ABC":
    print(f"   Componente {c} puro -> resistência ≈ {ms.params[c]:.1f}")
for par in ["A:B", "A:C", "B:C"]:
    v = ms.params[par]
    tipo = "SINERGIA" if v > 0 else "ANTAGONISMO"
    sig = "significativo" if ms.pvalues[par] < 0.05 else "não significativo"
    print(f"   {par}: {v:+.1f}  -> {tipo} ({sig}, p = {ms.pvalues[par]:.4f})")

# --- Otimizar dentro do simplex, com restrições realistas ---
def neg_resp(x):
    A, B = x; C = 1 - A - B
    if C < 0: return 1e6
    return -ms.predict(pd.DataFrame({"A":[A],"B":[B],"C":[C]}))[0]

# Restrições típicas de formulação: C >= 10% (por requisito funcional)
cons = [{"type":"ineq", "fun": lambda x: 1 - x[0] - x[1] - 0.10}]
best = min((optimize.minimize(neg_resp, x0, bounds=[(0,1),(0,1)], constraints=cons)
            for x0 in rng.uniform(0.05, 0.6, (30,2))), key=lambda r: r.fun)
Ao, Bo = best.x; Co = 1 - Ao - Bo
print(f"\nFORMULAÇÃO ÓTIMA (com restrição C ≥ 10%)")
print(f"   A = {Ao:.1%} | B = {Bo:.1%} | C = {Co:.1%}")
print(f"   Resistência prevista = {-best.fun:.2f}")
print(f"   Melhor componente puro = {max(ms.params[c] for c in 'ABC'):.2f}")
print(f"   => a mistura supera qualquer componente isolado (sinergia A-B)")

# Contorno ternário
n = 160
Ag, Bg = np.meshgrid(np.linspace(0,1,n), np.linspace(0,1,n))
Cg = 1 - Ag - Bg
mask = Cg >= 0
Z = np.full(Ag.shape, np.nan)
grid = pd.DataFrame({"A":Ag[mask], "B":Bg[mask], "C":Cg[mask]})
Z[mask] = ms.predict(grid)
fig, ax = plt.subplots(figsize=(6.5, 5.5))
cs = ax.contourf(Ag, Bg, Z, levels=22, cmap="viridis")
ax.contour(Ag, Bg, Z, levels=12, colors="white", linewidths=0.5)
plt.colorbar(cs, ax=ax, label="resistência")
ax.scatter(mix.A, mix.B, c="white", s=45, edgecolor="black", zorder=5)
ax.plot(Ao, Bo, "r*", ms=20, zorder=6)
ax.plot([0,1],[1,0], "k-", lw=1.5)
ax.set_xlabel("proporção de A"); ax.set_ylabel("proporção de B")
ax.set_title("Superfície de mistura no simplex\n(a hipotenusa é C = 0)")
ax.set_xlim(0,1); ax.set_ylim(0,1)
plt.tight_layout(); plt.show()
```

### Part 2 — Split-Plot Designs

**The problem.** Some factors are expensive or slow to change: an oven's temperature, a lot's raw material, a line's setup. Fully randomizing would require changing them on every run — often not feasible.

**The common, wrong practice:** run every combination of the easy factors within each level of the hard factor, then **analyze it as if it were a fully randomized factorial**. This is wrong, and the error has a known sign.

**The correct structure:**

- **Whole plot** — the factor that's hard to change. Large error, **few** degrees of freedom.
- **Split plot (subplot)** — the easy factors, randomized within each whole plot. Small error, many degrees of freedom.

$$y_{ijk} = \mu + \underbrace{\alpha_i + \delta_{ik}}_{\text{whole plot}} + \underbrace{\beta_j + (\alpha\beta)_{ij} + \varepsilon_{ijk}}_{\text{subplot}}$$

**There are two experimental errors**, and testing everything against the small error is the classic mistake:

> The hard-to-change factor ends up with tests that are **too optimistic** (p-values too small).
> The easy factors and the interactions end up, in practice, with **more** power than they'd have in a fully randomized design.

This second point is the good news that often gets overlooked: split-plot isn't just a patch for a constraint — it's **more efficient** for estimating the easy factors and interactions.

```py-r
--- python
import numpy as np
import pandas as pd
import statsmodels.formula.api as smf
from scipy import stats

rng = np.random.default_rng(6060)

# Forno (difícil de mudar) x tempo e pressão (fáceis)
n_fornadas_por_nivel = 4
linhas = []
wp = 0
for temp in [-1, 1]:
    for rep in range(n_fornadas_por_nivel):
        erro_wp = rng.normal(0, 1.6)          # erro da PARCELA PRINCIPAL (grande)
        for tempo in [-1, 1]:
            for pressao in [-1, 1]:
                y = (60 + 3.0*temp + 2.2*tempo + 1.0*pressao
                     + 2.6*temp*tempo + erro_wp + rng.normal(0, 0.5))
                linhas.append({"fornada": wp, "temp": temp, "tempo": tempo,
                               "pressao": pressao, "y": y})
        wp_atual = wp
    wp += 1
# corrigir identificador de fornada
d = pd.DataFrame(linhas)
d["fornada"] = np.repeat(np.arange(2*n_fornadas_por_nivel), 4)

print(f"{d.fornada.nunique()} fornadas × 4 corridas = {len(d)} observações")
print(f"O fator 'temp' muda apenas {d.fornada.nunique()} vezes, não {len(d)}.\n")

# --- ANÁLISE ERRADA: fatorial completamente aleatorizado ---
errada = smf.ols("y ~ temp*tempo*pressao", data=d).fit()
print("1) ANÁLISE ERRADA — como fatorial completamente aleatorizado")
print(errada.summary2().tables[1].round(4).loc[
    ["temp", "tempo", "pressao", "temp:tempo"]].to_string())

# --- ANÁLISE CORRETA: modelo misto com fornada como efeito aleatório ---
correta = smf.mixedlm("y ~ temp*tempo*pressao", data=d, groups=d["fornada"]).fit()
print("\n2) ANÁLISE CORRETA — split-plot (fornada = efeito aleatório)")
res = pd.DataFrame({"Coef": correta.params, "EP": correta.bse,
                    "p": correta.pvalues}).round(4)
print(res.loc[["temp", "tempo", "pressao", "temp:tempo"]].to_string())
print(f"\n   Var(fornada) = {float(correta.cov_re.iloc[0,0]):.4f} "
      f"(erro da parcela principal)")
print(f"   Var(resíduo) = {float(correta.scale):.4f} (erro da sub-parcela)")
print(f"   Rácio = {float(correta.cov_re.iloc[0,0])/float(correta.scale):.1f}x")

cmp = pd.DataFrame({
    "EP (análise errada)": errada.bse, "p (errada)": errada.pvalues,
    "EP (split-plot)": correta.bse, "p (split-plot)": correta.pvalues,
}).loc[["temp","tempo","pressao","temp:tempo"]].round(4)
cmp["EP subestimado por"] = (correta.bse/errada.bse).round(2)
print("\n3) COMPARAÇÃO")
print(cmp.to_string())
print("\n   • Para 'temp' (fator difícil), a análise errada subestima o erro-padrão")
print("     e produz um p-value demasiado pequeno: risco de declarar significativo")
print("     um efeito que não é.")
print("   • Para os fatores fáceis e a interação, os erros-padrão quase não mudam —")
print("     é o que torna o split-plot eficiente onde interessa.")
```

### Excel and Power BI

**Mixtures:** Scheffé's model (with no intercept, since $\sum x_i = 1$ makes the intercept redundant) is also fittable via `LINEST` as long as you force the absence of a constant:

```py-r
--- excel
' LINEST com o argumento constante = FALSO para forcar a ausencia de intercepto,
' condicao necessaria no modelo de Scheffe:
=LINEST(Y_range; X_componentes_range; FALSO; VERDADEIRO)
```

**Split-plot: here the honest answer is not to use Excel.** Analyzing a split-plot design requires two distinct error terms — one for the whole-plot factors (here, the oven) and one for the subplot factors — and Excel's standard ANOVA tools (including the Data Analysis ToolPak) **don't separate these two errors correctly**; applying them to a split-plot produces F tests with the wrong denominator for the whole-plot factors, falsely inflating their significance. This is precisely the trap described under "Common mistakes" below — treat it as a concrete reason not to replicate this design in Excel, even when the temptation to "just run a quick ANOVA" is strong. Use the mixed model (Python `statsmodels`/R `nlme`, as in Chapter 54), which already handles the two-error structure correctly.

### Common mistakes

**Mixtures**

1. **Using a factorial design on formulation components.** Singular matrix; meaningless results.
2. **Including a constant term in Scheffé's model.** It's redundant with $\sum x_i = 1$ and makes the model unidentifiable.
3. **Ignoring formulation constraints.** In practice there are always minimums and maximums per component. With constraints, the simplex-lattice doesn't work; use a D-optimal design over the constrained region.
4. **Forgetting the total amount.** If the process also depends on the total amount (not just the proportions), it's a **mixture-process** design, with process factors in addition to the components.

**Split-plot**

5. **Analyzing it as fully randomized.** The most common mistake, and the one that produces false positives on the factor that was most expensive to study.
6. **Too few whole plots.** With 2 batches per temperature level, the whole-plot degrees of freedom are far too few and the hard factor's test has no power at all. If the hard factor is the priority, replicate **batches**, not runs within a batch.
7. **Not recording the execution structure.** If no one noted which runs shared the same batch, the correct analysis becomes impossible afterward. **Record the randomization structure in the protocol, before running.**
