## Chapter 107: SQL for Quality Engineering
### The engineering question

*How do I, as a quality engineer, get the data without depending on someone in IT for every question?*

SQL is the highest-return skill per hour invested in all of PART XIII. It is not programming: it is five clauses and a handful of patterns. And it is the difference between waiting three days for a data pull and answering the question the moment it comes up in the meeting.

### The execution order (which is not the writing order)

```sql
SELECT      -- 5. what to return
FROM        -- 1. from where
JOIN        -- 2. combined with
WHERE       -- 3. filters ROWS (before grouping)
GROUP BY    -- 4. groups
HAVING      -- 6. filters GROUPS (after aggregating)
ORDER BY    -- 7. sorts
LIMIT       -- 8. trims
```

**The most common confusion is between `WHERE` and `HAVING`.** `WHERE` filters individual rows before aggregation; `HAVING` filters the resulting groups. "Parts produced in July" is `WHERE`; "part numbers with more than 100 defects" is `HAVING`.

**JOINs, in quality-engineering terms:**

| JOIN | Returns | When to use it in quality |
|---|---|---|
| `INNER` | Only what exists in both tables | Parts that have a recorded measurement |
| `LEFT` | Everything from the left, with nulls on the right | **Parts that should have a measurement and don't** ← the most valuable case |
| `FULL` | Everything from both | Reconciliation between systems |

> `LEFT JOIN ... WHERE right IS NULL` is the **data-completeness audit** pattern. It finds what's missing — and what's missing is often the most important information.

### Worked example: a complete quality database

The example below runs with Python's standard-library `sqlite3`, no installation required.

```py-r
--- python
import sqlite3
import pandas as pd
import numpy as np

rng = np.random.default_rng(2026)
con = sqlite3.connect(":memory:")

# ---------- Modelo de dados típico de qualidade ----------
con.executescript("""
CREATE TABLE fornecedor (
    id_fornecedor INTEGER PRIMARY KEY, nome TEXT, pais TEXT, classificacao TEXT);
CREATE TABLE lote (
    id_lote INTEGER PRIMARY KEY, id_fornecedor INTEGER, referencia TEXT,
    data_rececao TEXT, quantidade INTEGER);
CREATE TABLE peca (
    id_peca INTEGER PRIMARY KEY, id_lote INTEGER, id_maquina TEXT,
    data_producao TEXT, turno TEXT);
CREATE TABLE medicao (
    id_medicao INTEGER PRIMARY KEY, id_peca INTEGER, caracteristica TEXT,
    valor REAL, lsl REAL, usl REAL, id_instrumento TEXT);
CREATE TABLE nao_conformidade (
    id_nc INTEGER PRIMARY KEY, id_peca INTEGER, tipo_defeito TEXT,
    gravidade TEXT, custo REAL);
""")

fornecedores = [(1,"Alfa Metais","PT","A"), (2,"Beta Componentes","ES","B"),
                (3,"Gama Precisão","DE","A"), (4,"Delta Supply","CN","C")]
con.executemany("INSERT INTO fornecedor VALUES (?,?,?,?)", fornecedores)

lotes, pecas, medicoes, ncs = [], [], [], []
id_peca = id_med = id_nc = 1
qualidade_forn = {1: (10.00, 0.030), 2: (10.02, 0.055),
                  3: (10.00, 0.022), 4: (10.05, 0.075)}   # (média, sigma)

for id_lote in range(1, 61):
    f = int(rng.integers(1, 5))
    mes = int(rng.integers(1, 8))
    lotes.append((id_lote, f, f"REF-{rng.integers(100,105)}",
                  f"2026-{mes:02d}-{rng.integers(1,28):02d}", 40))
    mu, sd = qualidade_forn[f]
    for _ in range(40):
        maq = f"M{rng.integers(1,4)}"
        turno = str(rng.choice(["M","T","N"]))
        pecas.append((id_peca, id_lote, maq, f"2026-{mes:02d}-15", turno))
        # 4% das peças NÃO têm medição registada (falha de processo de dados)
        if rng.random() > 0.04:
            v = rng.normal(mu, sd)
            medicoes.append((id_med, id_peca, "diametro", v, 9.90, 10.10,
                             f"CAL-{rng.integers(1,4)}"))
            id_med += 1
            if v < 9.90 or v > 10.10:
                ncs.append((id_nc, id_peca, "fora_tolerancia",
                            str(rng.choice(["maior","menor"], p=[0.3,0.7])),
                            float(round(rng.uniform(8, 45), 2))))
                id_nc += 1
        id_peca += 1

con.executemany("INSERT INTO lote VALUES (?,?,?,?,?)", lotes)
con.executemany("INSERT INTO peca VALUES (?,?,?,?,?)", pecas)
con.executemany("INSERT INTO medicao VALUES (?,?,?,?,?,?,?)", medicoes)
con.executemany("INSERT INTO nao_conformidade VALUES (?,?,?,?,?)", ncs)
con.commit()

def q(sql, titulo=""):
    if titulo: print(f"\n{'='*70}\n{titulo}\n{'='*70}")
    df = pd.read_sql_query(sql, con)
    print(df.to_string(index=False))
    return df

print(f"Base criada: {len(lotes)} lotes, {len(pecas)} peças, "
      f"{len(medicoes)} medições, {len(ncs)} não conformidades")
```

```py-r
--- python
# ---------- 1. Scorecard de fornecedores (o relatório mais pedido) ----------
q("""
SELECT  f.nome                                   AS fornecedor,
        f.pais,
        f.classificacao                          AS classe,
        COUNT(DISTINCT l.id_lote)                AS lotes,
        COUNT(p.id_peca)                         AS pecas,
        COUNT(nc.id_nc)                          AS nao_conformes,
        ROUND(1000000.0 * COUNT(nc.id_nc) / COUNT(p.id_peca), 0) AS ppm,
        ROUND(COALESCE(SUM(nc.custo), 0), 2)     AS custo_falha_eur,
        ROUND(AVG(m.valor), 4)                   AS media_diametro,
        ROUND(
          (MAX(m.usl) - MIN(m.lsl)) /
          (6.0 * SQRT( AVG(m.valor*m.valor) - AVG(m.valor)*AVG(m.valor) )), 3
        )                                        AS Pp_aprox
FROM        fornecedor f
JOIN        lote       l  ON l.id_fornecedor = f.id_fornecedor
JOIN        peca       p  ON p.id_lote       = l.id_lote
LEFT JOIN   medicao    m  ON m.id_peca       = p.id_peca
LEFT JOIN   nao_conformidade nc ON nc.id_peca = p.id_peca
GROUP BY    f.id_fornecedor
ORDER BY    ppm DESC
""", "1. SCORECARD DE FORNECEDORES — PPM, custo e capability aproximada")

print("\nNota: o Pp aqui é aproximado (usa o desvio-padrão global de todas as peças")
print("do fornecedor). Serve para ordenar fornecedores, NÃO para um relatório de")
print("PPAP — esse exige o cálculo correto, com estabilidade verificada primeiro.")
```

```py-r
--- python
# ---------- 2. Auditoria de completude: peças SEM medição ----------
q("""
SELECT  l.referencia,
        f.nome                       AS fornecedor,
        p.id_maquina                 AS maquina,
        COUNT(*)                     AS pecas_sem_medicao
FROM        peca    p
JOIN        lote    l ON l.id_lote = p.id_lote
JOIN        fornecedor f ON f.id_fornecedor = l.id_fornecedor
LEFT JOIN   medicao m ON m.id_peca = p.id_peca
WHERE       m.id_medicao IS NULL          -- <<< o padrão de auditoria
GROUP BY    l.referencia, f.nome, p.id_maquina
HAVING      COUNT(*) >= 3
ORDER BY    pecas_sem_medicao DESC
LIMIT 10
""", "2. AUDITORIA DE COMPLETUDE — peças que deviam ter medição e não têm")

print("\nEste é o padrão LEFT JOIN + IS NULL. Numa auditoria de sistema, esta")
print("consulta responde diretamente ao requisito de evidência de inspeção.")
```

```py-r
# ---------- 3. Pareto de custo com percentagem acumulada (window function) ----------
q("""
WITH por_tipo AS (
    SELECT  nc.gravidade,
            COUNT(*)      AS ocorrencias,
            SUM(nc.custo) AS custo_total
    FROM    nao_conformidade nc
    GROUP BY nc.gravidade
)
SELECT  gravidade,
        ocorrencias,
        ROUND(custo_total, 2)                                        AS custo_eur,
        ROUND(100.0 * custo_total / SUM(custo_total) OVER (), 1)     AS pct,
        ROUND(100.0 * SUM(custo_total) OVER (ORDER BY custo_total DESC)
                    / SUM(custo_total) OVER (), 1)                   AS pct_acumulada
FROM     por_tipo
ORDER BY custo_total DESC
""", "3. PARETO DE CUSTO — com acumulada calculada em SQL (window functions)")
```

```py-r
--- python
# ---------- 4. Fora de especificação, por turno e máquina ----------
q("""
SELECT  p.turno,
        p.id_maquina                                    AS maquina,
        COUNT(*)                                        AS medicoes,
        SUM(CASE WHEN m.valor < m.lsl OR m.valor > m.usl
                 THEN 1 ELSE 0 END)                     AS fora_spec,
        ROUND(100.0 * SUM(CASE WHEN m.valor < m.lsl OR m.valor > m.usl
                               THEN 1 ELSE 0 END) / COUNT(*), 2) AS pct_fora,
        ROUND(AVG(m.valor), 4)                          AS media,
        ROUND(MIN(m.valor), 4)                          AS minimo,
        ROUND(MAX(m.valor), 4)                          AS maximo
FROM        medicao m
JOIN        peca    p ON p.id_peca = m.id_peca
GROUP BY    p.turno, p.id_maquina
HAVING      COUNT(*) > 20
ORDER BY    pct_fora DESC
LIMIT 8
""", "4. ESTRATIFICAÇÃO — a mesma pergunta, cortada por turno e máquina")

print("\nA estratificação é a ferramenta analítica mais subutilizada da qualidade.")
print("Uma taxa global de 2% pode esconder 0,3% em dois turnos e 8% num terceiro.")
```

```py-r
--- python
# ---------- 5. Rastreabilidade inversa: de uma reclamação até ao lote ----------
q("""
SELECT  nc.id_nc,
        nc.tipo_defeito,
        ROUND(nc.custo, 2)   AS custo,
        p.id_peca,
        p.id_maquina         AS maquina,
        p.turno,
        l.id_lote,
        l.referencia,
        l.data_rececao,
        f.nome               AS fornecedor,
        m.id_instrumento     AS instrumento,
        ROUND(m.valor, 4)    AS valor_medido
FROM        nao_conformidade nc
JOIN        peca       p ON p.id_peca       = nc.id_peca
JOIN        lote       l ON l.id_lote       = p.id_lote
JOIN        fornecedor f ON f.id_fornecedor = l.id_fornecedor
LEFT JOIN   medicao    m ON m.id_peca       = p.id_peca
ORDER BY    nc.custo DESC
LIMIT 6
""", "5. RASTREABILIDADE INVERSA — do defeito até ao fornecedor e ao instrumento")

print("\nEsta consulta é a espinha dorsal de uma investigação 8D e de um recall.")
print("Sem as chaves que ligam peça -> lote -> fornecedor -> instrumento, a")
print("contenção não consegue ser delimitada e passa a ser 'apanhar tudo'.")

# ---------- 6. Suspeita de deriva de instrumento ----------
q("""
SELECT  m.id_instrumento                     AS instrumento,
        COUNT(*)                             AS n,
        ROUND(AVG(m.valor), 4)               AS media,
        ROUND(AVG(m.valor) - 10.0, 4)        AS desvio_vs_nominal,
        ROUND(SQRT(AVG(m.valor*m.valor) - AVG(m.valor)*AVG(m.valor)), 4) AS sd
FROM     medicao m
GROUP BY m.id_instrumento
ORDER BY ABS(AVG(m.valor) - 10.0) DESC
""", "6. SINAL DE BIAS DE INSTRUMENTO — comparar médias entre instrumentos")

print("\nSe um instrumento apresenta média sistematicamente diferente dos outros")
print("sobre a mesma população de peças, isso é um sinal de BIAS (PARTE VI) e")
print("aciona uma verificação de calibração — não uma investigação do processo.")
con.close()
```

### SQL patterns every quality engineer should know

| Pattern | What it's for |
|---|---|
| `LEFT JOIN ... WHERE b.id IS NULL` | Finding missing records (completeness) |
| `SUM(CASE WHEN ... THEN 1 ELSE 0 END)` | Conditional counting in a single pass |
| `SUM(x) OVER (ORDER BY ...)` | Running totals — Pareto, CUSUM |
| `LAG(x) OVER (ORDER BY date)` | Difference from the previous observation — moving range |
| `ROW_NUMBER() OVER (PARTITION BY ...)` | Deduplicating, keeping the most recent record per part |
| `WITH ... AS (...)` (CTE) | Breaking complex queries into readable steps |
| `AVG(x*x) - AVG(x)*AVG(x)` | Variance when there's no `STDDEV` (as in SQLite) |

**Watch out for nulls.** `COUNT(column)` ignores nulls, `COUNT(*)` doesn't. `AVG` ignores nulls. `NULL <> 'A'` returns `NULL`, not true. In quality data, where the absence of a record *is* information, these differences change conclusions.

### Common mistakes

1. **Computing capability in SQL for an official report.** SQL aggregates well; it doesn't estimate $\sigma_{within}$, doesn't verify stability, and doesn't test distribution. Use it to extract and sort, not to conclude.
2. **`INNER JOIN` when the question is about what's missing.** It eliminates exactly the rows that matter.
3. **Confusing `WHERE` and `HAVING`.**
4. **Ignoring duplicates created by a JOIN.** A part with 3 measurements shows up 3 times; `COUNT(p.id_peca)` ends up counting measurements, not parts. Use `COUNT(DISTINCT ...)`.
5. **Dates as text without a consistent format.** Always store as ISO-8601 (`YYYY-MM-DD`), which sorts correctly as text.
6. **Extracting to Excel and losing traceability.** Save the query together with the result. In an audit, the question will be "how did you get this number?"
