## Chapter 22: Kanban: Sizing and Operation
### The engineering question

*How many cards?*

Kanban is often taught as "cards that authorize production" and left at that. But kanban only works if the number of cards is **calculated**. An arbitrary number produces either stockouts or useless inventory — and in either case the team wrongly concludes "kanban doesn't work here."

### The two fundamental types

| Type | Function | Circulates between |
|---|---|---|
| **Production kanban** | Authorizes making | Supermarket → upstream process |
| **Withdrawal kanban** | Authorizes moving | Downstream process → supermarket |

In simple systems, a single card does both jobs. In factories with distance between processes, separating them keeps movement and production from becoming coupled.

**Operating rules (Toyota's "six rules," in practical form):**

1. The downstream process withdraws only what's on the card — exact quantity and part number.
2. The upstream process produces only what the cards authorize, in the order they arrive.
3. **Nothing gets produced or moved without a card.** No exceptions: the exception destroys the system.
4. A defective part **never** moves forward with a card. The card stays held until there's a good part.
5. The number of cards should be progressively reduced — that's how kanban exposes problems.
6. The card physically travels with the material.

Rule 4 is what ties kanban to quality: in a well-run kanban system, **sending a defect downstream stops the line**. It's jidoka applied to material flow.

### The sizing formula

$$N = \frac{D \times LT \times (1 + \alpha)}{Q}$$

| Symbol | Meaning | Practical note |
|---|---|---|
| $N$ | Number of cards | Always round **up** |
| $D$ | Average demand per time unit | Use demand, not historical production |
| $LT$ | Replenishment lead time (from signal until the part is available) | Includes setup, queue, production, and transport |
| $\alpha$ | Safety factor | Typically 0.10–0.30; reflects variability |
| $Q$ | Quantity per container | Set by packaging/handling |

The honest parameter is $\alpha$. It's **not** a factory constant: it's the measure of the variability that hasn't been resolved yet. A defensible way to set it is from the observed variability of demand during the lead time:

$$\alpha \approx z \cdot \frac{\sigma_{D \cdot LT}}{\mu_{D \cdot LT}}$$

with $z$ chosen by the desired service level (1.65 for 95%, 2.33 for 99%).

> **Lowering $\alpha$ isn't an administrative decision.** Lowering the safety factor without lowering the real variability produces stockouts. The correct sequence is: reduce variability (SMED, TPM, heijunka) → recalculate $\alpha$ → pull cards.

### Worked example: size it, then test it

```py-r
--- python
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)

# --- Parâmetros do posto ---
D_media = 480          # peças/dia
D_sd = 95              # desvio-padrão da procura diária
LT_dias = 1.5          # lead time de reposição
Q = 40                 # peças por contentor
z = 1.65               # nível de serviço ~95%

# alpha derivado da variabilidade, e não arbitrado
sigma_LT = D_sd * np.sqrt(LT_dias)
mu_LT = D_media * LT_dias
alpha = z * sigma_LT / mu_LT

N_bruto = (D_media * LT_dias * (1 + alpha)) / Q
N = int(np.ceil(N_bruto))

print(f"Procura durante o lead time: média {mu_LT:.0f} ± {sigma_LT:.0f} peças")
print(f"alpha derivado             : {alpha:.3f}  ({alpha:.1%})")
print(f"N (bruto)                  : {N_bruto:.2f}")
print(f"N (cartões a emitir)       : {N}")
print(f"WIP máximo autorizado      : {N * Q} peças  "
      f"({N * Q / D_media:.2f} dias de procura)\n")

# --- Verificação por simulação: qual o nível de serviço real? ---
def simular_kanban(n_cartoes, dias=4000):
    stock = n_cartoes * Q
    em_transito = []          # (dia_de_chegada, quantidade)
    roturas = 0
    stock_medio = []
    for dia in range(dias):
        chegou = [q for d, q in em_transito if d == dia]
        stock += sum(chegou)
        em_transito = [(d, q) for d, q in em_transito if d != dia]

        procura = max(0, int(rng.normal(D_media, D_sd)))
        if procura > stock:
            roturas += 1
            procura = stock
        stock -= procura
        stock_medio.append(stock)

        # repor em múltiplos de contentor, respeitando o teto de cartões
        wip_total = stock + sum(q for _, q in em_transito)
        a_repor = int((n_cartoes * Q - wip_total) // Q)
        if a_repor > 0:
            em_transito.append((dia + int(np.ceil(LT_dias)), a_repor * Q))
    return 1 - roturas / dias, np.mean(stock_medio)

print("Sensibilidade ao número de cartões:")
tabela = []
for n in range(max(1, N - 4), N + 4):
    servico, st = simular_kanban(n)
    tabela.append({"Cartões": n, "WIP máx (pç)": n * Q,
                   "Nível de serviço": f"{servico:.1%}",
                   "Stock médio (pç)": round(st)})
df = pd.DataFrame(tabela)
df["<-- calculado"] = np.where(df["Cartões"] == N, "  <<<", "")
print(df.to_string(index=False))
```

**Engineering reading.** The simulation does the work the formula alone can't: it shows the **trade-off curve** between cards and service level. It's typically strongly nonlinear — there's a knee past which adding cards barely improves service and just adds stock.

The value computed by the formula should land near that knee. If it lands well to the right, $\alpha$ was inflated. If it lands to the left with poor service, the replenishment lead time is underestimated — usually because the queue ahead of the setup was forgotten.

### Common mistakes

1. **Sizing with historical production instead of demand.** If there were stockouts in the past, historical production is lower than demand and the kanban is born undersized.
2. **Lead time with only production time.** The replenishment time includes the queue ahead of the setup, which is usually the largest share.
3. **Kanban on erratic demand with no heijunka.** With very irregular demand, the required $N$ becomes so large the system stops making sense. Level first.
4. **Not recalculating.** $N$ should be reviewed when demand shifts to a new level (typically quarterly) and whenever the replenishment lead time changes.
5. **Electronic kanban that stops no one.** If the digital signal can be ignored with no consequence, it isn't kanban — it's a report.
